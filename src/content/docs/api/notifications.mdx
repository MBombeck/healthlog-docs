## Notification Preferences

```
GET /api/notifications/preferences
PUT /api/notifications/preferences
```

**Auth:** Session Cookie

Manages channel preferences and per-event opt-out settings for each channel.

```bash
curl -s https://your-instance.example.com/api/notifications/preferences \
  -H "Cookie: healthlog_session=abc123"
```

**Response:**

```json
{
  "data": {
    "channels": {
      "webPush": true,
      "telegram": true,
      "ntfy": false
    },
    "events": {
      "MEDICATION_REMINDER": { "webPush": true, "telegram": true, "ntfy": false },
      "COMPLIANCE_LOW": { "webPush": true, "telegram": false, "ntfy": false }
    }
  },
  "error": null
}
```

## Web Push

Browser push delivered through the standard [Push API](https://developer.mozilla.org/en-US/docs/Web/API/Push_API), authenticated with [VAPID](https://datatracker.ietf.org/doc/html/rfc8292) (Voluntary Application Server Identification) — the server proves its identity to the push service with a signed key pair rather than a shared secret.

### Subscribe

```
POST /api/notifications/web-push
```

**Auth:** Session Cookie

Registers a Web Push subscription.

```json
{
  "endpoint": "https://fcm.googleapis.com/fcm/send/...",
  "keys": {
    "p256dh": "...",
    "auth": "..."
  }
}
```

### Unsubscribe

```
DELETE /api/notifications/web-push
```

### VAPID Key

```
GET /api/notifications/vapid
```

**Auth:** None

Returns the public VAPID key required for Web Push subscriptions.

```json
{
  "data": {
    "publicKey": "BNx..."
  },
  "error": null
}
```

## Telegram

### Configuration

```
GET /api/settings/telegram
PUT /api/settings/telegram
```

**Auth:** Session Cookie

```json
{
  "botToken": "123456:ABC-...",
  "chatId": "987654321",
  "webhookEnabled": true
}
```

### Test Message

```
POST /api/settings/telegram/test
```

**Auth:** Session Cookie

Sends a test message through the configured Telegram bot.

```bash
curl -s -X POST https://your-instance.example.com/api/settings/telegram/test \
  -H "Cookie: healthlog_session=abc123"
```

## ntfy

[ntfy](https://docs.ntfy.sh/) is a simple HTTP-based pub-sub push service (self-hostable or via the public `ntfy.sh`); HealthLog publishes to a per-user topic.

### Configuration

```
GET /api/settings/ntfy
PUT /api/settings/ntfy
```

**Auth:** Session Cookie

```json
{
  "serverUrl": "https://ntfy.sh",
  "topic": "healthlog-alice",
  "authToken": "tk_..."
}
```

### Test Message

```
POST /api/settings/ntfy/test
```

**Auth:** Session Cookie

Sends a test message to the configured ntfy channel.

## APNs (Apple Push)

[Apple Push Notification service](https://en.wikipedia.org/wiki/Apple_Push_Notification_service) is the optional channel for the native iOS client. The server authenticates to Apple's gateway with a [JWT](https://datatracker.ietf.org/doc/html/rfc7519) signed by an Apple `.p8` key (token-based APNs). Unlike the per-user channels above, APNs is configured **server-wide via environment variables** — there is no per-user settings endpoint. If the variables are not all set, APNs is silently disabled and the dispatcher falls back to Web Push / Telegram / ntfy. The user-facing channel overview is on [Features → Notifications](/features/notifications/).

### Environment configuration

| Variable | Required | Description |
|---------|----------|-------------|
| `APNS_KEY_ID` | yes | 10-char key ID of the `.p8` auth key |
| `APNS_TEAM_ID` | yes | 10-char Apple Developer team ID |
| `APNS_BUNDLE_ID` | yes | Bundle-id of the signed iOS app; used as the APNs topic |
| `APNS_KEY` | one of | `.p8` PEM contents (multi-line or `\n`-escaped) |
| `APNS_KEY_B64` | one of | Base64-encoded `.p8` (escape-free alternative) |
| `APNS_KEY_FILE` | one of | Filesystem path to the `.p8` |
| `APNS_PRODUCTION` | no | `"true"` forces the production gateway |

```bash
APNS_KEY_ID="ABCD123456"
APNS_TEAM_ID="S8WDX4W5KX"
APNS_BUNDLE_ID="dev.healthlog.app"
APNS_KEY_B64="LS0tLS1CRUdJTi...="
```

All of `APNS_KEY_ID`, `APNS_TEAM_ID`, `APNS_BUNDLE_ID`, plus exactly one key source must be present together; otherwise the channel stays off (no crash, soft fallback).

### Device token registration

The iOS app registers its APNs device token through `POST /api/devices` (see [Native API Clients](/api/native-clients/)). The server then fans one push out per registered token, setting the push `topic` to `APNS_BUNDLE_ID`.

:::caution[Self-hosters must rebuild the iOS app]
The `.p8` key must belong to the same Apple Developer team that signed the app, and the topic (`APNS_BUNDLE_ID`) must equal the app's bundle-id. To use your own `.p8`, rebuild and re-sign the iOS client under your own bundle-id and team. See [Notifications → APNs](/features/notifications/#apns-apple-push) and the [iOS repo](https://github.com/MBombeck/healthlog-iOS).
:::
