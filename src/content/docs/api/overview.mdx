HealthLog exposes a [REST](https://en.wikipedia.org/wiki/REST)-style HTTP API:
resources (measurements, medications, mood entries, …) live under stable URLs,
and you act on them with the standard HTTP verbs (`GET`, `POST`, `PUT`,
`DELETE`). Every endpoint speaks JSON and wraps its payload in a consistent
response envelope.

## Base URL

All API endpoints are relative to your instance's base URL:

```
https://your-instance.example.com/api
```

## Response Format

Every response follows a consistent envelope format:

```json
{
  "data": { ... },
  "error": null
}
```

On errors:

```json
{
  "data": null,
  "error": "Validation failed: password must be at least 12 characters"
}
```

Some endpoints also include a `meta` object with pagination data:

```json
{
  "data": [ ... ],
  "error": null,
  "meta": {
    "total": 142,
    "limit": 20,
    "offset": 0
  }
}
```

## Authentication

HealthLog supports two authentication methods:

| Method | Usage | Header/Cookie |
|--------|-------|---------------|
| Session Cookie | Browser clients | `healthlog_session` cookie (automatic) |
| Bearer Token | External API calls | `Authorization: Bearer hlk_...` |

Browser clients ride a [session cookie](https://en.wikipedia.org/wiki/HTTP_cookie)
that is set and refreshed automatically after login. External callers use a
[bearer token](https://datatracker.ietf.org/doc/html/rfc6750) — the OAuth 2.0
`Authorization: Bearer …` scheme from RFC 6750. Bearer tokens are created through
the [token management](/api/external-ingest/) and are bound to specific
permissions.

## Rate Limiting

Protected endpoints include rate limit headers in every response:

| Header | Description |
|--------|-------------|
| `X-RateLimit-Remaining` | Remaining requests in the current window |
| `X-RateLimit-Reset` | Unix timestamp when the window resets |

When the limit is exceeded, the API returns `429 Too Many Requests`.

## HTTP Status Codes

The API uses standard
[HTTP status codes](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Status)
to signal the outcome of every request:

| Code | Meaning |
|------|---------|
| `200` | Success |
| `201` | Resource created |
| `204` | Success with no response body |
| `400` | Bad request |
| `401` | Not authenticated |
| `403` | Forbidden |
| `404` | Resource not found |
| `422` | Validation error (e.g. invalid field values) |
| `429` | Rate limit exceeded |
| `500` | Internal server error |

## Example Request

```bash
curl -s https://your-instance.example.com/api/auth/me \
  -H "Cookie: healthlog_session=abc123"
```

Response:

```json
{
  "data": {
    "id": "clx...",
    "username": "alice",
    "email": "alice@example.com",
    "role": "ADMIN"
  },
  "error": null
}
```
