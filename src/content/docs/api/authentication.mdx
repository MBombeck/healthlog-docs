## Registration

The first registered user is automatically assigned the `ADMIN` role.

```
POST /api/auth/register
```

**Rate Limit:** 5 requests / 15 minutes / IP

**Request Body:**

```json
{
  "username": "alice",
  "email": "alice@example.com",
  "password": "secure-password"
}
```

**Response** `201`:

```json
{
  "data": {
    "id": "clx...",
    "username": "alice",
    "email": "alice@example.com",
    "role": "ADMIN"
  },
  "error": null
}
```

## Login

```
POST /api/auth/login
```

**Rate Limit:** 5 requests / 15 minutes / IP

**Request Body:**

```json
{
  "email": "alice",
  "password": "secure-password"
}
```

The `email` field accepts either a username or an email address.

```bash
curl -s -c cookies.txt https://your-instance.example.com/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email": "alice", "password": "secure-password"}'
```

## Logout

```
POST /api/auth/logout
```

**Auth:** Session Cookie

Destroys the current session.

## Current User

```
GET /api/auth/me
```

**Auth:** Session Cookie or Bearer Token

Returns the current user profile. The `avatarUrl` is **self-hosted** — a relative
URL served from your own database (`/api/user/avatar/...?v=<ms>`), never a
third-party Gravatar request, so no email hash ever leaves your instance. It is
`null` until an avatar is uploaded, in which case clients render the
username-initials fallback.

**Response** `200`:

```json
{
  "data": {
    "id": "clx...",
    "username": "alice",
    "email": "alice@example.com",
    "role": "USER",
    "heightCm": 182,
    "dateOfBirth": "1990-05-15",
    "gender": "MALE",
    "timezone": "Europe/Berlin",
    "onboardingCompletedAt": "2026-01-12T08:00:00.000Z",
    "onboardingTourCompleted": true,
    "avatarUrl": "/api/user/avatar/clx...?v=1716663600000",
    "glucoseUnit": "mg/dL",
    "unitPreference": "metric",
    "lastReportPracticeName": null,
    "disableCoach": false,
    "fullName": null,
    "insurerName": null,
    "insuranceNumber": null
  },
  "error": null
}
```

- `unitPreference` — `"metric"` or `"imperial"`, the display-unit toggle from
  Settings → Display. Canonical storage stays SI; this only drives the
  render-time transform.
- `fullName`, `insurerName`, `insuranceNumber` — optional patient-identity
  fields used by the [health-record export](/features/export-import/). The
  insurance number is validated and encrypted at rest, and is decrypted
  fail-soft (reads `null` rather than failing the whole profile fetch on a
  key-rotation gap).

## Update Profile

```
PUT /api/auth/profile
```

**Auth:** Session Cookie

**Request Body:**

```json
{
  "email": "new@example.com",
  "heightCm": 182,
  "dateOfBirth": "1990-05-15",
  "gender": "MALE"
}
```

All fields are optional. Only the provided fields are updated.

---

## Change Password

```
POST /api/auth/password
```

**Auth:** Session Cookie
**Rate Limit:** 5 requests / 15 minutes / user

**Request Body:**

```json
{
  "currentPassword": "old-password",
  "newPassword": "new-secure-password"
}
```

After a successful password change, all existing sessions are invalidated.

## Registration Status

```
GET /api/auth/registration-status
```

**Auth:** None

Checks whether registration is enabled (e.g. whether an admin already exists).

```json
{
  "data": {
    "registrationEnabled": true
  },
  "error": null
}
```

## Passkeys (WebAuthn)

HealthLog supports passwordless authentication via
[WebAuthn / passkeys](https://www.w3.org/TR/webauthn-2/) — the W3C standard for
public-key credentials. The private key never leaves the authenticator (a
device biometric or hardware key); the server only ever stores and verifies the
public key, so there is no shared secret to phish or leak.

### Register a Passkey

```
POST /api/auth/passkey/register-options   — Retrieve options
POST /api/auth/passkey/register-verify    — Complete registration
```

### Passkey Login

```
POST /api/auth/passkey/login-options      — Retrieve challenge
POST /api/auth/passkey/login-verify       — Complete login
```

### Manage Passkeys

```
GET    /api/auth/passkeys                 — List all passkeys for the user
DELETE /api/auth/passkeys/[id]            — Remove a passkey
```

**Auth:** All passkey endpoints (except login) require an active session.
