## Registration

The first registered user is automatically assigned the `ADMIN` role.

```
POST /api/auth/register
```

**Rate Limit:** 5 requests / 15 minutes / IP

**Request Body:**

```json
{
  "username": "alice",
  "email": "alice@example.com",
  "password": "secure-password"
}
```

**Response** `201`:

```json
{
  "data": {
    "id": "clx...",
    "username": "alice",
    "email": "alice@example.com",
    "role": "ADMIN"
  },
  "error": null
}
```

## Login

```
POST /api/auth/login
```

**Rate Limit:** 5 requests / 15 minutes / IP

**Request Body:**

```json
{
  "email": "alice",
  "password": "secure-password"
}
```

The `email` field accepts either a username or an email address. On success the
server sets a `healthlog_session`
[session cookie](https://en.wikipedia.org/wiki/HTTP_cookie) that subsequent
browser requests send automatically.

```bash
curl -s -c cookies.txt https://your-instance.example.com/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email": "alice", "password": "secure-password"}'
```

## Current User

```
GET /api/auth/me
```

**Auth:** Session Cookie or Bearer Token

Returns the current user profile. The `avatarUrl` is **self-hosted** — a relative
URL served from your own database (`/api/user/avatar/...?v=<ms>`), never a
third-party Gravatar request, so no email hash ever leaves your instance. It is
`null` until an avatar is uploaded, in which case clients render the
username-initials fallback.

**Response** `200`:

```json
{
  "data": {
    "id": "clx...",
    "username": "alice",
    "email": "alice@example.com",
    "role": "USER",
    "heightCm": 182,
    "dateOfBirth": "1990-05-15",
    "gender": "MALE",
    "timezone": "Europe/Berlin",
    "onboardingCompletedAt": "2026-01-12T08:00:00.000Z",
    "onboardingTourCompleted": true,
    "avatarUrl": "/api/user/avatar/clx...?v=1716663600000",
    "glucoseUnit": "mg/dL",
    "unitPreference": "metric",
    "lastReportPracticeName": null,
    "disableCoach": false,
    "fullName": null,
    "insurerName": null,
    "insuranceNumber": null
  },
  "error": null
}
```

- `unitPreference` — `"metric"` or `"imperial"`, the display-unit toggle from
  Settings → Display. Canonical storage stays SI; this only drives the
  render-time transform.
- `fullName`, `insurerName`, `insuranceNumber` — optional patient-identity
  fields used by the [health-record export](/features/export-import/). The
  insurance number is validated and encrypted at rest, and is decrypted
  fail-soft (reads `null` rather than failing the whole profile fetch on a
  key-rotation gap).

## Update Profile

```
PUT /api/auth/profile
```

**Auth:** Session Cookie

**Request Body:**

```json
{
  "email": "new@example.com",
  "heightCm": 182,
  "dateOfBirth": "1990-05-15",
  "gender": "MALE",
  "fullName": "Alex Example",
  "insurerName": "Example Health",
  "insuranceNumber": "A123456789"
}
```

All fields are optional. Only the provided fields are updated. `fullName`,
`insurerName`, and `insuranceNumber` are the patient-identity fields used by the
[health-record export](/features/export-import/#health-record-export-pdf--fhir-r4)
cover page and the FHIR `Patient` resource. The insurance number is validated
(German KVNR mod-10) and encrypted at rest.

## Display-Unit Preference

```
GET   /api/auth/me/unit-preference
PATCH /api/auth/me/unit-preference
```

**Auth:** Session Cookie or Bearer Token

Reads or sets the global metric/imperial display preference:

```json
{ "unitPreference": "imperial" }
```

This only drives the render-time transform — stored and exported values stay
canonical SI. The current value is also returned on [`/api/auth/me`](#current-user).

## Avatar

```
POST   /api/user/avatar        — Upload a self-hosted avatar (multipart)
DELETE /api/user/avatar        — Remove the avatar (falls back to initials)
GET    /api/user/avatar/[id]   — Fetch the stored image
```

**Auth:** Session Cookie

Avatars are stored in your own database and served from your instance — there is
no third-party Gravatar request, so no email hash ever leaves the server. The
upload accepts JPEG, PNG, or WebP. `/api/auth/me` returns the `avatarUrl` with a
`?v=<ms>` cache-buster that changes on each upload.

## Change Password

```
POST /api/auth/password
```

**Auth:** Session Cookie
**Rate Limit:** 5 requests / 15 minutes / user

**Request Body:**

```json
{
  "currentPassword": "old-password",
  "newPassword": "new-secure-password"
}
```

After a successful password change, all existing sessions are invalidated.

## Login Branch Check

```
POST /api/auth/check-user
```

**Auth:** None
**Rate Limit:** 30 requests / 15 minutes / IP

Given an `identifier` (username or email), reports which sign-in path the UI
should offer — `not_found`, `passkey_only`, `email_fallback`, or `exists` — so
the login form can route a passkey-only account straight to WebAuthn. The
identifier is hashed before it touches any audit row, so no raw email or
username lands in operator-readable logs.

```json
{ "identifier": "alice" }
```

## Token Refresh

```
POST /api/auth/refresh
```

Rotates a native client's bearer token. The iOS app and other long-lived
clients exchange their current refresh credential for a fresh access token here
rather than re-prompting for a password. See [Native Clients](/api/native-clients/)
for the full token-rotation contract.

## Trusted Devices

```
GET    /api/auth/me/devices        — List registered devices
DELETE /api/auth/me/devices/[id]   — Revoke a device
```

**Auth:** Session Cookie or Bearer Token

Lists the native clients/sessions bound to your account and lets you revoke one
remotely (e.g. a lost phone). Revoking a device invalidates its bearer token.

## ChatGPT-Codex Device Authorization

```
POST /api/auth/codex/device-start    — Begin the device-code flow
POST /api/auth/codex/device-poll     — Poll for approval
POST /api/auth/codex/disconnect      — Disconnect the linked account
```

**Auth:** Session Cookie

Connects a ChatGPT-Codex account for AI insights using the
[OAuth 2.0 Device Authorization Grant (RFC 8628)](https://datatracker.ietf.org/doc/html/rfc8628).
`device-start` returns a short `userCode` and a `verificationUrl`; the user
approves on `chatgpt.com` from any device, and `device-poll` exchanges the
approval for tokens once granted. This avoids a redirect back to your own
domain — the device-grant flow is designed for exactly this no-callback case.
The pending device-auth secret is held in an encrypted, httpOnly cookie scoped
to the 15-minute approval window. See [Settings → AI Providers](/settings/ai-providers/).

## Passkeys (WebAuthn)

HealthLog supports passwordless authentication via
[WebAuthn / passkeys](https://www.w3.org/TR/webauthn-2/) — the W3C standard for
public-key credentials. The private key never leaves the authenticator (a
device biometric or hardware key); the server only ever stores and verifies the
public key, so there is no shared secret to phish or leak.

### Register a Passkey

```
POST /api/auth/passkey/register-options   — Retrieve options
POST /api/auth/passkey/register-verify    — Complete registration
```

### Passkey Login

```
POST /api/auth/passkey/login-options      — Retrieve challenge
POST /api/auth/passkey/login-verify       — Complete login
```

### Manage Passkeys

```
GET    /api/auth/passkeys                 — List all passkeys for the user
DELETE /api/auth/passkeys/[id]            — Remove a passkey
```

**Auth:** All passkey endpoints (except login) require an active session.
