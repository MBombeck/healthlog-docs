When two providers report the same metric — a Withings scale and an Apple Watch
both logging weight, or HealthKit and Fitbit both reporting steps — HealthLog
keeps every row as an audit trail but applies a per-metric **source priority** to
decide which reading is canonical for display and analytics.

This is the practical guide to adjusting that ladder. For the reasoning behind
the two-ladder design, see
[Why source priority works the way it does](/explanation/source-priority/).

## The default ladders

HealthLog ranks sources differently depending on the metric class, because the
right answer differs. The main defaults, highest first:

| Metric | Default order |
| --- | --- |
| Weight | Withings, Apple Health, Health Connect, manual, then your own pushes (token, MCP, Telegram), WHOOP, Fitbit, Google Health |
| Blood pressure | Withings, Apple Health, Health Connect, manual, then your own pushes |
| Pulse | Withings, Apple Health, Fitbit, Google Health, Oura, Polar, manual, then your own pushes |
| SpO₂ | Withings, WHOOP, Fitbit, Google Health, Oura, Polar, Apple Health, Health Connect, manual, then your own pushes |
| Steps | Apple Health, Health Connect, Withings, Fitbit, Google Health, Oura, Polar, Strava, manual, then your own pushes |
| Sleep, HRV | WHOOP, Fitbit, Google Health, Oura, Polar, Apple Health, Withings |
| Resting heart rate, breathing rate | WHOOP, Fitbit, Google Health, Oura, Polar, Apple Health, Health Connect, Withings |
| Recovery | WHOOP, Oura, Polar, the computed proxy |

"Your own pushes" are readings from a [measurement token](/guides/ingest-token/)
(source `EXTERNAL`), from an assistant through MCP, and replies to a Telegram
reminder, in that order. Active energy and distance follow the steps order
without Strava; body fat and body temperature follow the weight order.

Cumulative activity metrics (steps, active energy, distance, flights) pick
exactly **one source per day** so they are never double-counted. Weekly,
monthly and yearly figures add up those days; they never pick one source for
the whole period. The pulse, heart rate variability and blood oxygen charts
follow the ladder per day too, and the blood pressure chart takes both values
of a day from the same source. Glucose has no priority setting and keeps all
its sources.

A source that a metric's ladder does not name ranks below every source it
does name. When none of the colliding sources appear in the ladder, every row
is kept.

## Adjust the ladder

Open **Settings → Source priority** (`/settings/sources`). For each metric (or
metric class) you can:

- Reorder the source ladder with the up/down arrow buttons.
- Set an optional **device-type tie-break** so two devices reporting under the
  same source resolve deterministically.

Changes are per user and audit-logged. The API surface is
`GET` / `PUT /api/auth/me/source-priority`.

## Where values come from

**Where values come from** (`/insights/sources`) shows what the ladder decides,
day by day. Open it from **Settings → Source priority** or from the **Where
these values come from** link on a metric page. Pick a metric and a day to see
every source that delivered a reading that day, how many readings and from
which devices, which source the charts use, and why (the only source, highest
in your order, or a tie broken by name). **Compare two sources** lines up two
sources over a range: the days both have, the average from each, and the
average difference. The source is chosen per day from midnight to midnight
UTC, the same way the charts choose it.

## What happens to the losing rows

Nothing is deleted. A reading that loses the priority contest stays stored,
tagged with its source, and drops out of the active display
and analytics. If you later disconnect the winning source or reorder the ladder,
the previously-hidden rows resurface — no data was lost.

## Worked example

You sync a Withings scale and also import Apple Health (which received the same
weighing second-hand via the Health Mate app):

- **Weight** (point): Withings wins for display; the Apple Health row stays as
  audit trail.
- **Steps** (cumulative): if a ScanWatch feeds HealthKit, the Apple-Health-
  aggregated day wins; the Withings step rows stay in the database.

Override either default under **Settings → Source priority** if your setup
differs — for instance, if you trust a Fitbit's resting heart rate over a
Withings estimate.
