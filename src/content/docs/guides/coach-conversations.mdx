Since v1.39.4 a Coach answer shows more than its text. You see which parts of
your record the Coach read while it works, the values it read as a table or a
chart, how a figure was worked out, and up to three suggestions for what to ask
next. When a question could mean several things, the Coach asks back with a
few choices instead of guessing.

All of this is built by the server from what the Coach actually read. The AI
model writes the answer text; it never writes a step label, a table, a chart,
the method line or the wording of a suggestion.

:::note[Which setups show it]
The sources list, tables, charts, method line and suggestions come from the
Coach reading your record piece by piece, which needs a provider that can call
tools: OpenAI, Anthropic, ChatGPT (Codex) and the OpenAI-compatible gateway
entry can. The [**Local** provider](/guides/ai-providers/#local-endpoints)
cannot, and neither can a provider chain that includes it. With such a chain
the Coach reads a summary of your whole record at once, as before: the sources list shows one line, **Reading
your record summary**, and there are no tables, charts or suggestions.

An iPhone app from before v1.39.4 shows the answer as before, without these
parts.
:::

## What the Coach looked at

While the Coach works, a line above its answer names the source it is reading,
for example **Checking: Blood pressure, last 90 days…**. Once the answer is
complete, the line reads **Looked at 3 sources**. Tap it to open the list: one
row per source, with the time window and how many readings it found, or why it
found none, such as **no readings**, **no readings in this window**,
**switched off** for a module that is off, or **couldn't be read**. Several
reads of the same source, such as this month and the month before, count as
one source.

The list shows only what the Coach read, never a value. A row names a part of
your record, a window and a count. The name of a lab test, which comes from
your own records, never appears there.

## Tables of your values

When the Coach reads a stretch of days, weeks or months, or a set of workouts,
sleep nights, lab results or medication adherence, it keeps what it read as a
table. The tables the answer relies on appear under the answer. Tables it read
without pointing at them sit under **Data used** inside the **What I'm looking
at** disclosure.

- **The latest rows in view.** A table over time shows its latest 12 periods,
  still in date order, and any other table its first 12 rows. **Show all**
  opens every row in a scrolling area whose header stays in place.
- **Absence stays visible.** A day, week or month without a reading shows as
  `—`, never as zero, and a screen reader hears "no reading".
- **Weeks and months mean one thing per metric.** A total such as steps,
  active energy, distance or daylight is the sum of its days. A level such as
  blood pressure, weight or pulse is the average of its days. The numbers are
  the ones the app's own charts show for that period.
- **The default grain follows the window.** Up to 90 days are listed by day,
  the last 12 months by week, and all time by month, unless you ask for another
  grain.
- **From an earlier answer.** When the Coach shows a table again that an
  earlier answer in the same conversation read, the table says **From an
  earlier answer** with that answer's date. It is the stored table with the
  values it had then, not a new read. Ask for fresh figures to have the Coach
  read again.

A table keeps the values the answer was given with. A reading you edit or sync
later does not change a table an earlier answer showed.

### Copying a table

The copy button beside a table's title offers two forms:

- **Copy for spreadsheet** puts the table on the clipboard as tab-separated
  values and as an HTML table, so a spreadsheet gets a grid and a document gets
  a table.
- **Copy as text** gives aligned plain text, for a message or a note.

Both copy every row, not only the ones on screen, with the column headings and
their units. A cell that a spreadsheet would read as a formula (one starting
with `=`, `+`, `-`, `@` or `|`) gets a leading apostrophe so it stays text; a
plain negative number is left alone. The button needs the browser's clipboard,
which browsers offer only over HTTPS or on `localhost`, so a server reached
over plain HTTP shows no copy button.

## Charts

The server picks a chart for each table from its shape and the metric. The
model has no say in it.

| Table | Chart |
| --- | --- |
| A level metric over time (blood pressure, weight, pulse, sleep, mood, …) | A line. Blood pressure draws systolic and diastolic together |
| A total over time (steps, active energy, distance, flights, daylight, …) | Vertical bars, one per day, week or month |
| Counts per category (workouts by sport) | Bars, horizontal once there are more than six categories. The eight largest are drawn and the rest are grouped as **Other** |
| How often each range of values came up | A histogram |
| Lab results, or a table with a single row | No chart, the table only |

A chart never mixes units: a table with values in different units draws the
first value column, plus a second only when it shares the unit.

A table with a chart has a **Chart** / **Table** toggle. A table under the
answer opens as the chart unless you asked for the table, a table under
**Data used** opens as the table, and the toggle does not change what is
stored. The chart has a text name for screen readers that points to the table
view for every value.

**Histograms.** When a conversation already holds a table of days, ask how
often your values fell into each range ("how often was my blood pressure in
each range?") and the Coach shows that table as a histogram: how many days
fell into each range. The ranges are 5 mmHg wide for blood pressure, 5 bpm for
pulse, 0.5 kg for weight, 30 minutes for sleep, 10 mg/dL for glucose and 1,000
for steps; other metrics get a width worked out from the spread of the values.
There are at most 20 ranges. A histogram
needs at least 10 values. With fewer, the table keeps its usual chart rather
than drawing a histogram of noise.

## How a figure was worked out

Inside **What I'm looking at**, the line **How this was worked out** lists each
source the answer rests on with its window, the number of readings and how
they were combined, for example "Blood pressure, last 90 days: 142 readings,
weekly averages · Sleep, last 30 days: no readings in this window". A source
the Coach found nothing for says so, and a table taken from an earlier answer
is marked **from an earlier answer**. The line is written by the server from
what was read. It carries counts, never a health value.

**Asking "Is that right?"** When you question a figure in a conversation that
holds a table ("is that right?", "that seems high"), the Coach is instructed
to name the source and window it used, read them again, and compare. If the
second read differs, it corrects the answer and says what changed; if it
matches, it says so. It is told never to adjust a figure to fit what you
expected.

## Follow-up suggestions

Under the latest answer, up to three buttons suggest what to ask next. Each
appears only when what it asks for is grounded in what the Coach just read:

| Suggestion | Offered when |
| --- | --- |
| **Show as a chart** / **Show as a table** | A table of this answer has a chart and is shown in the other view |
| **Compare with the period before** | A table over time covers the current period |
| **Compare with a year earlier** | The same, over at most 90 days, and your readings of that metric go back more than a year |
| **Look further back** | Your record holds readings older than the table's window |
| **See also:** *metric* | The Coach found a link between a metric it read and another metric you record |
| **Keep looking** | The Coach ran out of reading rounds before it finished (see below) |

The comparison and wider-window suggestions are offered for metrics read by
day, week or month; glucose, medication adherence and workouts have their own
reads and get none of them. The model may say which of the allowed suggestions
fit its answer best, which only changes their order. It cannot add one, and it
never words one.

**Show as a chart** and **Show as a table** are answered from the stored table
without asking the model at all. The reply says "Here are the same figures from
my last answer, unchanged." The others start a normal Coach turn.

Suggestions sit under the latest answer only, disappear while the Coach is
answering, and do not appear beside a clarifying question. To turn them off,
switch off **Suggest follow-up questions** under **Settings → Coach** in
**Coach settings**, then **Save**. That also turns off **Keep looking**.

## Keep looking

The Coach reads your record in at most three rounds per answer. When it still
wanted to read more after the third, it answers with what it has and offers
**Keep looking**. Tapping it continues the same question: the Coach is told what
it already read, so it can show those tables again instead of reading them a
second time, and goes on from there. An answer can be continued once; the
continued answer offers no further **Keep looking**.

## When the Coach asks back

If a question stays ambiguous, such as "how is my pulse?" when you record
pulse, resting heart rate and walking heart rate, the Coach replies with one
short question and a card above the message box: **The Coach has a question**,
with two to four choices. Tap one, or type your own answer; the card says when
a typed answer works too.

- The question is about which metric, which time window, or something only you
  can tell (then there are no choices, and you type the answer).
- Metric choices only name metrics your record holds. If fewer than two
  remain, there is nothing to choose between, and the question stays a plain
  reply without a card.
- The Coach asks at most once in a row; a second question right after the
  first gets no card. It is instructed never to ask about doses, medication
  changes or diagnoses, and a question that trips the reply screening loses
  its choices.

## What the model sees and what you see

A table's values are health data, so they are handled as such:

- **Stored encrypted.** The tables are kept with the answer, encrypted with
  AES-256-GCM like the conversation itself. Only a description (which source,
  window and grain, and how many rows) is stored readable, never a value.
  Deleting the conversation deletes its tables. See
  [Encryption at rest](/explanation/encryption-at-rest/).
- **The model reads a summary, you see the table.** For a table of days, weeks
  or months, the model gets the number of readings, the average, lowest and
  highest value, the first and last period and at most 60 values, capped at
  about 1,500 tokens. You see every row. The figures in the answer are checked
  against what the model was given.
- **Earlier tables stay on the server.** In a later turn the model sees only a
  short description of the tables earlier answers read (source, window, row
  count), never their values. To use one again, it asks the server to show the
  stored table.
- **Excluded metrics never reach the model.** A metric you excluded under
  **Exclude metrics** in Coach settings, or whose module is switched off, is
  not read on any turn. An earlier table of that metric is no longer named to
  the model and cannot be shown again.
- **Switched-off modules hide their tables.** If you later switch off the
  module a stored table belongs to, the table is not shown ("This table is
  hidden because its module is switched off") and is not even decrypted.
  Switch the module back on and it returns.

Your stored tables stay readable while the Coach is unavailable, like the
conversations they belong to.

## Cost

A table of days, weeks or months adds its summary, at most about 1,500
tokens, to what the model reads.
**Show as a chart** and **Show as a table** cost nothing: no model call, no
share of your AI budget. The other suggestions and **Keep looking** are normal
turns and cost what any question costs. A clarifying question ends the turn
early, so it costs less than an answer. Every message, a tapped suggestion
included, counts toward the limit of 20 Coach messages a minute.

## Limits

| What | Limit |
| --- | --- |
| Tables per answer | 6 |
| Rows per table | 400, the latest kept; the table then says "Showing the latest 400 of *n* rows" |
| Stored tables per answer | 128 KB before encryption; tables past it are dropped from the end, before the answer is shown |
| Rows shown before **Show all** | 12 |
| Sources in the list | 12 per answer; later reads still happen but get no row |
| Reading rounds per answer | 3, then **Keep looking** |
| Follow-up suggestions | 3, under the latest answer only |
| Choices on a clarifying question | 4 |
| Earlier tables the model is told about | 3 from each of the last 5 answers that have tables |
| Histogram | At least 10 values, at most 20 ranges |

## For API clients

The stream, the new frames (`step`, `result`, `followUps`, `clarification`) and
the request fields for tapping a suggestion (`followUp`) or answering a question
(`clarification`) are described in the
[OpenAPI document](https://github.com/MBombeck/HealthLog/blob/main/docs/api/openapi.yaml).
A stored answer carries only the tables' descriptions; the values come from
`GET /api/insights/chat/{id}/messages/{messageId}/results`. See
[API endpoints](/reference/api-endpoints/#insights--coach).
