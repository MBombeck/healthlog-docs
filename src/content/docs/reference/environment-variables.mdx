This reference mirrors `.env.production.example` and `scripts/env-manifest.json`
in the main repository. The `pnpm check-env` CI step enforces that every variable
declared required in the manifest has a placeholder in the example file, so the
two never drift.

:::caution[The compose `environment:` block is a whitelist]
A variable in `.env` reaches the container **only** if it is also listed under
`environment:` in `docker-compose.yml`. Docker Compose reads `.env` for `${VAR}`
substitution at compose-up time, but does not forward arbitrary vars into the
container. When you add a new optional var, add it to the whitelist too — the
tables below flag the variables that are **not** whitelisted by default.
:::

## Core

`DATABASE_URL`, `API_TOKEN_HMAC_KEY` and a valid encryption key are checked at
startup and abort the container; the remaining rows are required for a working
deployment but have compose defaults.

| Variable | Purpose |
| --- | --- |
| `DATABASE_URL` | Postgres connection string. The compose default appends `connection_limit` + `pool_timeout`. |
| `POSTGRES_PASSWORD` | Password for the bundled `db` service. `openssl rand -hex 32`. |
| `NEXT_PUBLIC_APP_URL` | Public URL embedded in OAuth redirects, webhook callbacks, deep links. |
| `APP_URL` | Server-side mirror of the above, used by background workers. Must match. |
| `ENCRYPTION_KEY` | AES-256-GCM key for at-rest secrets. 64 hex chars. Required unless `ENCRYPTION_KEYS` is set. |
| `API_TOKEN_HMAC_KEY` | HMAC-SHA256 key for hashing Bearer tokens, refresh tokens and web session cookies. 64 hex chars. |

:::caution[Rotating `API_TOKEN_HMAC_KEY` signs everyone out]
Since v1.30.33 the browser session cookie is a random secret stored only as an
HMAC under this key, the same way Bearer and refresh tokens already were.
Rotating the key therefore invalidates every issued `hlk_*` token **and** every
browser session — users sign in again, and any automation holding a token needs
a new one. Plan it like a password change, not a config tweak.
:::

## Session, proxy & database pool

| Variable | Default | Purpose |
| --- | --- | --- |
| `SESSION_COOKIE_SECURE` | tracks `NODE_ENV=production` | Force or disable the cookie `Secure` flag. Set `false` for trusted plain-HTTP LANs. |
| `TRUST_PROXY_HOPS` | `1` | How many `X-Forwarded-For` hops to trust. See [reverse proxy](/guides/reverse-proxy/). On the compose whitelist since v1.37.33. |
| `TRUST_CF_CONNECTING_IP` | unset | Set `1` **only** behind Cloudflare to trust the `cf-connecting-ip` header. |
| `DATABASE_POOL_MAX` | `20` | Total Postgres connection budget for the process, not the Prisma ceiling: pg-boss takes 2 of it and Prisma gets the rest (18 at the default). Not whitelisted by default, so `DB_CONNECTION_LIMIT` is the knob that reaches the container. |
| `DB_CONNECTION_LIMIT` / `DB_POOL_TIMEOUT` | `20` / `20` | The compose file feeds them into the `connection_limit` and `pool_timeout` query params of the default `DATABASE_URL`, and the app also reads both directly (`src/lib/db.ts`), where they take precedence over `DATABASE_POOL_MAX` and over the URL's query params. |
| `DATABASE_STATEMENT_TIMEOUT_MS` | `60000` | Statement timeout applied to every database session, in milliseconds. `0` disables it and restores the unbounded behaviour. |
| `HEALTHLOG_PROCESS_TYPE` | `all` | `all` / `web` / `worker` process split. |
| `HEALTHLOG_IMAGE_REF` | `:latest` | **Compose-level substitution only**: the suffix of the `app` image reference. `:v1.38.0` pins a tag, `@sha256:<digest>` pins the immutable digest. See [pin the image by digest](/guides/updates-and-deploy/#pin-the-image-by-digest). |

## OIDC SSO (optional)

Sign in through a self-hosted identity provider (Authentik, Keycloak, Authelia,
and the like). Setting all three of issuer / client id / client secret enables
the "Sign in with SSO" button on the login page; setting none leaves it
disabled.

| Variable | Purpose |
| --- | --- |
| `OIDC_ISSUER_URL` | Provider issuer URL (discovery document served at `<issuer>/.well-known/openid-configuration`). |
| `OIDC_CLIENT_ID` / `OIDC_CLIENT_SECRET` | The confidential client credentials. |
| `OIDC_SCOPES` | Space-separated scopes requested at authorization. Default `openid email profile`. |
| `OIDC_BUTTON_LABEL` | Label on the login page's SSO button. Default `Single Sign-On`. |
| `OIDC_ONLY` | `true` disables password/passkey login server-side. Only takes effect when the provider group above is fully configured, so a half-configured group never locks every user out. |

:::caution[`OIDC_ONLY` and the iOS app]
The native iOS client signs in via an OIDC handoff of its own, so `OIDC_ONLY`
works with iOS builds that ship that flow. An older iOS build that only knows
password/passkey login is locked out of sign-in entirely.
:::

## Device integrations (optional)

Withings, WHOOP, Fitbit (classic), and Google Health credentials are
**per-user, pasted in Settings and encrypted in the database** — they have no
env-var path. Oura, Polar, and Strava accept a shared instance-wide app via
env, with a per-user override in Settings (for Strava the per-user pair is the
primary path — see [Connect Strava](/guides/connect-strava/)). The
`*_REDIRECT_URI` overrides are only needed when the callback origin differs
from `NEXT_PUBLIC_APP_URL`.

| Variable | Purpose |
| --- | --- |
| `WITHINGS_WEBHOOK_SECRET` | Path-segment secret hardening the Withings webhook URL. |
| `WITHINGS_REDIRECT_URI` | Callback override for [Withings](/guides/connect-withings/). |
| `WHOOP_REDIRECT_URI` | Callback override for [WHOOP](/guides/connect-whoop/). |
| `WHOOP_WEBHOOK_SECRET` | Path segment + HMAC body-signature key for the WHOOP webhook. |
| `FITBIT_REDIRECT_URI` | Callback override for [classic Fitbit](/guides/connect-fitbit/). |
| `GOOGLE_HEALTH_REDIRECT_URI` | Callback override for [Google Health](/guides/connect-google-health/). |
| `OURA_CLIENT_ID` / `OURA_CLIENT_SECRET` | Shared [Oura](/guides/connect-oura/) app; per-user Settings values win. |
| `OURA_REDIRECT_URI` | Callback override for Oura. |
| `POLAR_CLIENT_ID` / `POLAR_CLIENT_SECRET` | Shared [Polar](/guides/connect-polar/) app; per-user Settings values win. |
| `POLAR_REDIRECT_URI` | Callback override for Polar. |
| `STRAVA_CLIENT_ID` / `STRAVA_CLIENT_SECRET` | Optional shared [Strava](/guides/connect-strava/) app fallback; per-user Settings credentials are the primary path and always win. |
| `STRAVA_REDIRECT_URI` | Callback override for Strava; defaults to `${NEXT_PUBLIC_APP_URL}/api/strava/callback`. |
| `NIGHTSCOUT_PRIVATE_ORIGINS` | Nightscout origins on your own network the per-user connection form should accept, comma-separated (e.g. `http://nightscout.lan:1337`). Without it a private address is refused as an SSRF target. See [Connect Nightscout](/guides/connect-nightscout/). |
| `INTEGRATION_FAILURE_ALERT_THRESHOLD` | Consecutive failures before an integration is reported as persistently failing and notified about. Default `3`, minimum `1`. |

## APNs — iOS push (all-or-none)

Missing any one disables APNs silently.

| Variable | Purpose |
| --- | --- |
| `APNS_KEY_ID` / `APNS_TEAM_ID` / `APNS_BUNDLE_ID` | Apple Developer identifiers. |
| `APNS_KEY_B64` | The `.p8` key, base64-encoded — the **recommended** form, immune to newline mangling by deployment panels. Precedence: `APNS_KEY_B64` > `APNS_KEY` > `APNS_KEY_FILE`. |
| `APNS_KEY` / `APNS_KEY_FILE` | Raw PEM contents, or a path to the file. Both are on the compose whitelist alongside `APNS_KEY_B64`. |
| `APNS_PRODUCTION` | Force the production APNs gateway; default follows each device's registered environment. |
| `APNS_CRITICAL_ENTITLEMENT` | Set `true` only if the iOS build carries Apple's Critical Alerts entitlement; otherwise urgent alerts degrade to time-sensitive. |

The `.p8` must be scoped **"Sandbox & Production"** — a Sandbox-only key fails
with `BadEnvironmentKeyInToken` on production builds. See
[troubleshooting](/self-hosting/troubleshooting/).

## Email (SMTP) notification channel

Setting host + port + from enables the email channel; user/pass are optional.

| Variable | Purpose |
| --- | --- |
| `SMTP_HOST` / `SMTP_PORT` / `SMTP_FROM` | Server, port, and sender address. |
| `SMTP_USER` / `SMTP_PASS` | Credentials, when the relay requires auth. |
| `SMTP_SECURE` | `true` = implicit TLS (usually 465); otherwise STARTTLS (587). |

## IP geolocation (sign-in overview)

| Variable | Purpose |
| --- | --- |
| `GEOLITE2_DIR` | Directory of mounted MaxMind GeoLite2 `.mmdb` files. Since v1.37.1 the resolver reads them first and goes online only for an address they cannot place. |
| `MAXMIND_LICENSE_KEY` | A free MaxMind licence key. Set it and the worker downloads the GeoLite2 City + ASN databases into `GEOLITE2_DIR` itself at boot, refreshed monthly. The third way to supply the databases, no rebuild or manual mount; a mounted database still wins. |
| `IP_GEO_LOOKUP_URL` | Alternate lookup provider; default is ipwho.is. |
| `IP_GEO_LOOKUP_DISABLED` | Disable third-party IP lookups entirely (no geo egress). Also silences the one-time admin notice about online lookups, since there is nothing to warn about. |
| `IP_GEO_ALLOW_INSECURE` | Explicitly allow a plain-HTTP lookup provider; refused otherwise. |

## Audit-trail retention

| Variable | Default | Purpose |
| --- | --- | --- |
| `AUDIT_LOG_RETENTION_DAYS` | `365` | How long rows in `audit_logs` survive, in days. A daily job does the pruning. |

The floor is 7. A smaller value, a non-numeric one or a negative one is ignored
and the default applies, so a window entered in seconds by mistake cannot empty
a fresh table.

:::note[This number is published, not only enforced]
Two surfaces state it back to the user rather than printing a constant.
**Settings → Shared access** captions the activity list with the window it can
see, and the dialog that ends somebody else's access says how long "who entered
what" stays answerable. Both take the value the server resolved from this
variable, so an instance running 90 says 90 in both places. The API carries it
as `retentionDays` on `GET /api/account/activity` and `GET /api/account/grants`.

That makes shortening it a decision rather than a tidy-up on an instance where
households share records: a delegate's entry is permanent, and the name attached
to it lives only in the audit trail. See
[What a shared record is](/explanation/record-sharing/#why-a-delegates-entry-is-stored-as-the-owners).
:::

## Further retention (optional)

| Variable | Default | Purpose |
| --- | --- | --- |
| `COACH_MESSAGE_RETENTION_DAYS` | `365` | How long Coach conversations survive, in days. Floor 30. Like the audit window, this number is stated back to the user on the Data & Privacy page. |
| `HOST_METRIC_RETENTION_DAYS` | `7` | How long the host CPU / memory samples behind the admin monitoring charts are kept, in days. |

## AI (optional)

| Variable | Purpose |
| --- | --- |
| `ALLOW_LOCAL_AI_PRIVATE_HOSTS` | Let the SSRF guard reach private AI endpoints. Preferred form is a comma-separated host allowlist (`ollama.lan, 10.0.0.5`) — only those hosts pass. The legacy `true` opens **every** private host and remains accepted; unset / `false` allows none. |
| `INSIGHTS_RATE_LIMIT_PER_HOUR` | Bounds `POST /api/insights/generate` per user per hour (default 10). |
| `INSIGHTS_MAX_TOKENS` | Completion-token budget per insight generation. Default `2500`, clamped to 500–8000. Raise it when a verbose local model truncates its JSON mid-answer. |
| `NATIVE_CANVAS` | Override for the native canvas renderer (document thumbnails, scanned-PDF rasterization). Default auto-detects AVX2 on Linux x64 and disables cleanly on CPUs without it. `off` force-disables; `on` force-enables (crashes the process on a CPU that truly lacks AVX2). |
| `DOCUMENT_AI_LIMIT_PER_HOUR` | Per-user hourly ceiling for the document-AI actions (extract, suggest, summarise and index share one bucket). Default `6`, clamped to 1–1000. |
| `ADMIN_AI_BASE_URL_ALLOWLIST` | Extra hosts the **admin-configured** AI base URL may point at, on top of the built-in public providers. Comma-separated bare hostnames. It widens the admin setting only; per-user BYO keys keep the pinned public-host posture either way. |
| `CODEX_MODEL` / `CODEX_MODEL_FALLBACK_CHAIN` | Codex (ChatGPT sign-in) model slugs. The first pins one slug ahead of the built-in chain; the second replaces the chain outright, comma-separated. Reach for them when the provider rotates a slug and requests start failing with 503. |
| `COACH_EXPERIMENT_VERDICT` | `1` surfaces reviewed n-of-1 experiment outcomes in the Coach snapshot. Off by default; the review worker records outcomes either way. |

## Build-time only (not runtime)

`NEXT_PUBLIC_*` vars are inlined into the client bundle at **build time**. The
pre-built GHCR image ignores them at runtime, so they are deliberately absent
from the compose whitelist. Setting them in a deploy panel's runtime tab has no
effect.

| Variable | Purpose |
| --- | --- |
| `NEXT_PUBLIC_DASHBOARD_SNAPSHOT` | `false` falls back to the legacy four-cell dashboard path. |
| `NEXT_PUBLIC_APP_VERSION` / `NEXT_PUBLIC_APP_BUILD_SHA` / `NEXT_PUBLIC_APP_BUILT_AT` | Stamped from the GHCR tag during CI build; surfaced by `/api/version`. |

Telegram bot tokens and ntfy settings are configured **per user** in
notification settings; error-tracking URLs live in the **admin panel**. All
are stored encrypted in the database — not as environment variables.
Device-integration credentials (Withings, WHOOP, Fitbit, Google Health,
Strava) are per-user in Settings, likewise encrypted.
