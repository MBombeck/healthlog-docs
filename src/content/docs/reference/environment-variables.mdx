This reference mirrors `.env.production.example` and `scripts/env-manifest.json`
in the main repository. The `pnpm check-env` CI step enforces that every variable
declared required in the manifest has a placeholder in the example file, so the
two never drift.

:::caution[The compose `environment:` block is a whitelist]
A variable in `.env` reaches the container **only** if it is also listed under
`environment:` in `docker-compose.yml`. Docker Compose reads `.env` for `${VAR}`
substitution at compose-up time, but does not forward arbitrary vars into the
container. When you add a new optional var, add it to the whitelist too — the
tables below flag the variables that are **not** whitelisted by default.
:::

## Core — required for boot

The app refuses to boot without these.

| Variable | Purpose |
| --- | --- |
| `DATABASE_URL` | Postgres connection string. The compose default appends `connection_limit` + `pool_timeout`. |
| `POSTGRES_PASSWORD` | Password for the bundled `db` service. `openssl rand -hex 32`. |
| `NEXT_PUBLIC_APP_URL` | Public URL embedded in OAuth redirects, webhook callbacks, deep links. |
| `APP_URL` | Server-side mirror of the above, used by background workers. Must match. |
| `ENCRYPTION_KEY` | AES-256-GCM key for at-rest secrets. 64 hex chars. Required unless `ENCRYPTION_KEYS` is set. |
| `API_TOKEN_HMAC_KEY` | HMAC-SHA256 key for hashing Bearer tokens, refresh tokens and web session cookies. 64 hex chars. |

:::caution[Rotating `API_TOKEN_HMAC_KEY` signs everyone out]
Since v1.30.33 the browser session cookie is a random secret stored only as an
HMAC under this key, the same way Bearer and refresh tokens already were.
Rotating the key therefore invalidates every issued `hlk_*` token **and** every
browser session — users sign in again, and any automation holding a token needs
a new one. Plan it like a password change, not a config tweak.
:::

## Encryption key map

The modern multi-key path; see [key rotation](/guides/encryption-key-rotation/).

| Variable | Purpose |
| --- | --- |
| `ENCRYPTION_KEYS` | JSON map, e.g. `{"v1":"<hex>","v2":"<hex>"}`. |
| `ENCRYPTION_ACTIVE_KEY_ID` | The key id new writes use, e.g. `v2`. |

## Session, proxy & database pool

| Variable | Default | Purpose |
| --- | --- | --- |
| `SESSION_COOKIE_SECURE` | tracks `NODE_ENV=production` | Force or disable the cookie `Secure` flag. Set `false` for trusted plain-HTTP LANs. |
| `TRUST_PROXY_HOPS` | `1` | How many `X-Forwarded-For` hops to trust. See [reverse proxy](/guides/reverse-proxy/). |
| `TRUST_CF_CONNECTING_IP` | unset | Set `1` **only** behind Cloudflare to trust the `cf-connecting-ip` header. |
| `DATABASE_POOL_MAX` | `20` | The Prisma pool ceiling the app itself reads. |
| `DB_CONNECTION_LIMIT` / `DB_POOL_TIMEOUT` | `20` / `20` | **Compose-level substitutions only** — they feed the `connection_limit` and `pool_timeout` query params of the default `DATABASE_URL`. The app never reads them directly; with a hand-written `DATABASE_URL`, set the query params yourself. |
| `HEALTHLOG_PROCESS_TYPE` | `all` | `all` / `web` / `worker` process split. |

## Device integrations (optional)

Withings, WHOOP, Fitbit (classic), and Google Health credentials are
**per-user, pasted in Settings and encrypted in the database** — they have no
env-var path. Oura, Polar, and Strava accept a shared instance-wide app via
env, with a per-user override in Settings (for Strava the per-user pair is the
primary path — see [Connect Strava](/guides/connect-strava/)). The
`*_REDIRECT_URI` overrides are only needed when the callback origin differs
from `NEXT_PUBLIC_APP_URL`.

| Variable | Purpose |
| --- | --- |
| `WITHINGS_WEBHOOK_SECRET` | Path-segment secret hardening the Withings webhook URL. |
| `WITHINGS_REDIRECT_URI` | Callback override for [Withings](/guides/connect-withings/). Not whitelisted by default. |
| `WHOOP_REDIRECT_URI` | Callback override for [WHOOP](/guides/connect-whoop/). |
| `WHOOP_WEBHOOK_SECRET` | Path segment + HMAC body-signature key for the WHOOP webhook. |
| `FITBIT_REDIRECT_URI` | Callback override for [classic Fitbit](/guides/connect-fitbit/). Not whitelisted by default. |
| `GOOGLE_HEALTH_REDIRECT_URI` | Callback override for [Google Health](/guides/connect-google-health/). Not whitelisted by default. |
| `OURA_CLIENT_ID` / `OURA_CLIENT_SECRET` | Shared [Oura](/guides/connect-oura/) app; per-user Settings values win. |
| `OURA_REDIRECT_URI` | Callback override for Oura. |
| `POLAR_CLIENT_ID` / `POLAR_CLIENT_SECRET` | Shared [Polar](/guides/connect-polar/) app; per-user Settings values win. |
| `POLAR_REDIRECT_URI` | Callback override for Polar. |
| `STRAVA_CLIENT_ID` / `STRAVA_CLIENT_SECRET` | Optional shared [Strava](/guides/connect-strava/) app fallback; per-user Settings credentials are the primary path and always win. |
| `STRAVA_REDIRECT_URI` | Callback override for Strava; defaults to `${NEXT_PUBLIC_APP_URL}/api/strava/callback`. |

## APNs — iOS push (all-or-none)

Missing any one disables APNs silently.

| Variable | Purpose |
| --- | --- |
| `APNS_KEY_ID` / `APNS_TEAM_ID` / `APNS_BUNDLE_ID` | Apple Developer identifiers. |
| `APNS_KEY_B64` | The `.p8` key, base64-encoded — the **recommended** form, immune to newline mangling by deployment panels. Precedence: `APNS_KEY_B64` > `APNS_KEY` > `APNS_KEY_FILE`. |
| `APNS_KEY` / `APNS_KEY_FILE` | Raw PEM contents, or a path to the file. |
| `APNS_PRODUCTION` | Force the production APNs gateway; default follows each device's registered environment. |
| `APNS_CRITICAL_ENTITLEMENT` | Set `true` only if the iOS build carries Apple's Critical Alerts entitlement; otherwise urgent alerts degrade to time-sensitive. |

The `.p8` must be scoped **"Sandbox & Production"** — a Sandbox-only key fails
with `BadEnvironmentKeyInToken` on production builds. See
[troubleshooting](/self-hosting/troubleshooting/).

## Email (SMTP) notification channel

Setting host + port + from enables the email channel; user/pass are optional.

| Variable | Purpose |
| --- | --- |
| `SMTP_HOST` / `SMTP_PORT` / `SMTP_FROM` | Server, port, and sender address. |
| `SMTP_USER` / `SMTP_PASS` | Credentials, when the relay requires auth. |
| `SMTP_SECURE` | `true` = implicit TLS (usually 465); otherwise STARTTLS (587). |

## Web Push (VAPID)

The admin panel is the primary home for VAPID keys (stored encrypted in the

| Variable | Purpose |
| --- | --- |
| `VAPID_PUBLIC_KEY` / `VAPID_PRIVATE_KEY` | The VAPID key pair. |
| `VAPID_SUBJECT` | `mailto:` contact embedded in pushes. |

## AI (optional)

| Variable | Purpose |
| --- | --- |
| `ALLOW_LOCAL_AI_PRIVATE_HOSTS` | Let the SSRF guard reach private AI endpoints. Preferred form is a comma-separated host allowlist (`ollama.lan, 10.0.0.5`) — only those hosts pass. The legacy `true` opens **every** private host and remains accepted; unset / `false` allows none. |
| `INSIGHTS_RATE_LIMIT_PER_HOUR` | Bounds `POST /api/insights/generate` per user per hour (default 10). |
| `INSIGHTS_MAX_TOKENS` | Completion-token budget per insight generation. Default `2500`, clamped to 500–8000. Raise it when a verbose local model truncates its JSON mid-answer. |
| `NATIVE_CANVAS` | Override for the native canvas renderer (document thumbnails, scanned-PDF rasterization). Default auto-detects AVX2 on Linux x64 and disables cleanly on CPUs without it. `off` force-disables; `on` force-enables (crashes the process on a CPU that truly lacks AVX2). |

## Build-time only (not runtime)

`NEXT_PUBLIC_*` vars are inlined into the client bundle at **build time**. The
pre-built GHCR image ignores them at runtime, so they are deliberately absent
from the compose whitelist. Setting them in a deploy panel's runtime tab has no
effect.

| Variable | Purpose |
| --- | --- |
| `NEXT_PUBLIC_DASHBOARD_SNAPSHOT` | `false` falls back to the legacy four-cell dashboard path. |
| `NEXT_PUBLIC_APP_VERSION` / `NEXT_PUBLIC_APP_BUILD_SHA` / `NEXT_PUBLIC_APP_BUILT_AT` | Stamped from the GHCR tag during CI build; surfaced by `/api/version`. |

Telegram bot tokens and ntfy settings are configured **per user** in
notification settings; error-tracking URLs live in the **admin panel**. All
are stored encrypted in the database — not as environment variables.
Device-integration credentials (Withings, WHOOP, Fitbit, Google Health,
Strava) are per-user in Settings, likewise encrypted.
