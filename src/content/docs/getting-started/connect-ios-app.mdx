The native iPhone app is on the
[App Store](https://apps.apple.com/app/id6769501341), and a free beta with the
newest builds runs on [TestFlight](https://testflight.apple.com/join/bucuTBpa).
It speaks the same API as the web client. What it does once connected is
described on the [iOS app](/ios/ios-app/) page.

## Connect

1. Install the app from the [App Store](https://apps.apple.com/app/id6769501341)
   (or the beta from [TestFlight](https://testflight.apple.com/join/bucuTBpa)).
2. On first launch, enter your instance's public URL
   (`https://your-instance.example.com`). The app needs a reachable HTTPS origin
   with a valid certificate: set the
   [public hostname](/getting-started/first-steps/#point-the-instance-at-a-public-hostname)
   and a [reverse proxy](/guides/reverse-proxy/) first.
3. Sign in with a passkey, with your username or e-mail and password, or
   through your instance's single-sign-on provider, which opens in a system
   browser sheet and returns to the app. An instance running `OIDC_ONLY=true`
   offers only single sign-on. The app keeps its tokens in the iOS Keychain and
   renews them by itself; signing out revokes them on the server.
4. Grant HealthKit read and write access for the metric types you want synced.

## Push notifications (APNs)

The App Store and TestFlight app schedules medication reminders on the phone
itself, so you need nothing on the server for them. A self-hosted server
cannot send APNs push to that build; for reminders from the server, use Web
Push, ntfy or Telegram. Why, and what a self-built copy of the app needs, is
under [Reminders and push](/ios/ios-app/#reminders-and-push).
