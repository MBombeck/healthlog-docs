The dashboard ships with a sensible default layout, but the right order depends on what you actually track. If you don't take medication, the compliance widget is noise. If glucose is your daily focus, it should be the first thing you see. HealthLog lets you show/hide and reorder every widget on the dashboard.

## First-paint snapshot & nightly pre-generation

A cold dashboard load no longer staggers tile by tile. The above-the-fold strip is assembled in a single round-trip from `GET /api/dashboard/snapshot`, which reads the tile data from the rollup tier plus the pre-generated daily briefing, so the tiles arrive together. It is a pure data read — no language model is reachable from that path. On a rollup-coverage miss the heavy slice comes back as deferred rather than blocking the strip, and the snapshot plus the analytics queries poll on a shared interval so an open dashboard picks up new readings without a manual reload.

The daily briefing and the comprehensive insight are warmed **overnight** by a budget-gated background job, so opening `/insights` is a cache read instead of a synchronous model call. If the cache is cold (a brand-new account, or before the first nightly run), the page shows a *preparing* state rather than blocking the request. See [Background Jobs](/reference/data-model/) for the schedule.

## Score rings

The dashboard hero can carry up to **three score rings**, picked from a closed
set of four: **readiness**, **recovery**, **sleep score**, and **today's
doses**. Select and reorder them under **Settings → Dashboard** — changes
apply instantly, and the order you set is the order the hero renders.

Rings are honest about their inputs:

- A ring only renders when its module is enabled **and** it has data — a
  disabled sleep module or an empty recovery history simply drops the ring
  rather than painting a zero.
- The **dose ring** is the default single ring. It shows today's dose progress
  ("1 / 3 taken") in the medication colour. The band reads green only when
  every scheduled dose is taken and stays at a calm pending tone until then —
  never red, because a morning with doses still ahead is not an alert. On days
  with no scheduled doses it does not render at all.

The ring preference is part of your dashboard layout, so it follows you across
devices like the rest of the layout settings.

## Customize the Layout

1. Open the dashboard and tap the **Customize** icon in the top right (or **Settings → Dashboard**). Personal target values (BP, BMI, glucose, pulse) live in their own section at **Settings → Health Targets**.
2. Toggle widgets on or off with the visibility switch.
3. Drag the handle on the left of each widget to reorder.
4. Save. Your layout persists per device and per user.

Available widgets:

- Quick Add buttons
- Weight summary
- Blood pressure summary
- Glucose summary
- Pulse summary
- BMI card
- Heart-rate variability
- Blood oxygen (SpO₂)
- Breathing rate
- Wrist temperature
- Muscle mass
- Body water
- Bone mass
- Mood snapshot
- Medication compliance
- Today's reminders
- Recent achievements card
- AI Insight cards (per metric)

### Tiles for more metrics

Since v1.28.52 the tile strip covers more of what your devices already record.
Alongside the long-standing weight, blood-pressure, glucose and pulse tiles,
the dashboard can show:

- **Heart-rate variability**, **blood oxygen (SpO₂)**, **breathing rate**, and
  **wrist temperature** — the overnight and spot-check vitals a wearable
  reports. See [heart-rate variability](/knowledge/hrv/),
  [blood oxygen](/knowledge/spo2/), [respiratory rate](/knowledge/respiratory-rate/),
  and [body temperature](/knowledge/temperature/) for how to read each.
- **Muscle mass**, **body water**, and **bone mass** — the body-composition
  readings a smart scale reports beyond weight and body fat. See
  [body composition](/knowledge/body-composition/).

Each tile is **conditional**: it appears only once your account actually holds
that reading — from a connected device, an import, or a manual entry — so an
account that has never recorded a breathing rate never sees an empty breathing-
rate tile. Once a metric has data, its tile joins the strip and picks up the
same [7-day trend chip](#7-day-trend-on-every-tile) and per-metric colour as the
rest.

Like every other widget, the new tiles are **toggleable and reorderable** under
**Settings → Dashboard** — hide the ones you don't follow, drag the ones you do
to the top. The [tile / chart split](#tile-and-chart-toggles-separately) applies
here too, so you can keep a metric's tile without its chart.

### Tile and chart toggles, separately

Each metric on the dashboard appears twice: as a small **tile** in the top strip (single number, trend chip) and as a fuller **chart** in the row below. Those two surfaces have separate visibility switches in the layout settings — the row header reads "Tile / Chart" (EN) or "Kachel / Chart" (DE).

So if you want to see a tile for blood pressure but not the chart, you can. Existing saved layouts keep behaving as before — one switch controls both surfaces — until you flip the new toggle for that metric.

## Reset to Defaults

The Customize panel has a **Reset to defaults** button. It restores the original order and visibility for every widget, but it doesn't delete any data — it only clears the layout preference.

:::tip
If you only want to hide the AI Insight cards (e.g., you haven't configured a provider yet), toggle them off here rather than disabling AI globally. The provider stays configured for the Doctor Report PDF.
:::

## Mobile vs. Desktop

The layout is shared across breakpoints. Widgets you hide on desktop are also hidden on mobile. The order is the same, but the grid collapses to a single column on small screens.

The dashboard's measurement-tile strip uses a true CSS Grid track with a 9 rem floor per tile. Every tile takes the same share of the row; on narrow viewports the row wraps rather than triggering a horizontal scroll. The **BP-in-target** tile shows three independent windows side by side (7d / 30d / all-time), each computed from its own window via `computeBpInTargetWindows()`, so the three numbers can legitimately differ. The chart strip below the tiles auto-buckets its data on long ranges — daily for ≤ 90 days, weekly mean for 91–730 days, monthly mean beyond — with an inline chip showing which bucket is active. The mood chart follows the same thresholds, so a long history of daily mood entries no longer paints a noisy spaghetti line — you see weekly means past 90 days, monthly means past 730.

### 7-day trend on every tile

Every metric tile in the top strip shows a coloured `(±N.N)` next to the value. That delta is the 7-day trend: the average of the last 7 days minus the average of the 7 days before that, in the metric's own units. The label below the value reads "7d trend" (EN) / "7T-Trend" (DE) instead of the previous "7d average". The colour follows what's good for that metric — green for "up is good" (steps, sleep), orange for "up is concerning" (BP, BMI), muted for "neutral" (weight). One glance tells you which way the metric is moving.

The trend label is consistent across **every** chart, tile, and subtitle — there is no mix of "7d average" and "7d trend" depending on which surface you're on, and the indicator appears for mood and medication-compliance just like it does for the vitals charts. Long ranges fall back to a split-half mean delta when the per-week rate would round to zero, so the ±N never reads `0.0` when there's a real movement underneath.

### Chart polish

Every dashboard chart and the matching detail pages share the same visual baseline. Blood pressure, weight, pulse, body fat, sleep, steps, mood, and medication-compliance charts ship with:

- **Smooth, animated entry** — 600 ms ease-out on the line. The animation respects `prefers-reduced-motion` and snaps to final state for users who prefer reduced motion.
- A **rich tooltip** on hover or tap that includes the date and the value in the metric's units.
- An **explicit empty state** for sparse data (fewer than three readings in the visible range) instead of a degenerate one-or-two-point line.

The chart aesthetic is a clean line — no gradient fills under the lines, just a single coloured stroke against the card background. The mood chart drops the emoji glyphs at the data points; plain coloured dots sit on the line, and the y-axis already labels each integer (very low / low / okay / good / great), so the chart stays scannable. The emoji still appears in the tooltip when you hover or tap a point. The medication-compliance chart keeps the 80% threshold and 100% goal reference lines and adds a "−N pp vs. target" tooltip delta.

### Mobile chart layout

The chart card header switches to a mobile-first stack below `sm` — title plus chips on row 1, range tabs plus the cog right-aligned on row 2 with `flex-nowrap`, so the tabs always own a single row down to 280 px (Galaxy Fold compact). The bucket-aggregation chip and comparison captions hide on mobile to free horizontal budget. A new `useViewportWidth` hook + `x-axis-density` helper caps the visible x-axis ticks at 4 (Fold) / 6 (Pixel 5 / iPhone 12) / 8 (small tablet) / 10 (desktop), wired into HealthChart, MoodChart, MedicationComplianceChart and ComplianceLineChart, so the medication chart no longer overloads with one tick per day.

### Per-chart overlay toggles

Every chart card has a small cog button next to its header. Tap it for a popover with three independent switches:

- **7-day trend** — paints the personal-baseline line (your 90-day median, labelled "Your normal" / "Dein Mittel") on top of the chart, plus a numeric trend indicator next to the headline. Off by default.
- **Trend arrow** — adds the small ↑ / ↓ direction-arrow chip to the headline. Off by default.
- **Target range** — shades the metric's healthy band across the chart background (sys 120–139, weight ±5% of personal target, etc.). Off by default.

Defaults are all off, so the default look is a clean line. Each switch is **per chart, per user** — the BP chart can have target-range on while the weight chart stays off. State is persisted in your account (`User.dashboardWidgetsJson.chartOverlayPrefs`), so it survives reload and follows you across devices. The personal-baseline reference line only renders when the Trend switch on that specific chart is enabled.

### Comparison overlays

The **comparison toggle** — *off / vs. last month / vs. last year* — is a single global preference under **Settings → Dashboard**. The picker lives in `User.dashboardWidgetsJson.comparisonBaseline` and every chart consumes it. The cog menu on each chart card still handles trend, trend-arrow, and target-range overlays separately. With the toggle on, the prior period renders as a dimmed line beneath the current line, and a delta callout (Δ ±N) appears next to the headline value. The two periods share the same x-axis — the prior-period series is forward-shifted so each point sits directly under its current-period sibling, so any difference is a vertical offset you can spot at a glance.

The AI insights surface narrates the comparison ("your average BP improved by 4 mmHg vs. last month") when the toggle is active. See [Comparison views](/dashboard/comparison/) for the full walk-through.

Once you finish the onboarding checklist, the dashboard stops re-fetching the checklist gates on every load — opening the dashboard is roughly a second faster for established accounts because two background requests no longer fire. Insights chart bundles also load on demand on the **Insights** page, so the first paint is faster for everyone.

## What's Not Customizable

- The top navigation bar
- The sidebar (collapsible, but not reorderable)
- The Quick Add menu items (driven by which metrics you actively log)

Those are intentional — they're navigation, not content.
