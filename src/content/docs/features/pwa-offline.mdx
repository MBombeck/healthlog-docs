HealthLog is a [Progressive Web App](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps) (PWA) that can be installed on any device and works offline for core functionality. A PWA is a regular website enhanced with two browser platform features: a [Web App Manifest](https://developer.mozilla.org/en-US/docs/Web/Manifest) (a small JSON file that tells the browser the app's name, icons, and how it should launch) and a [Service Worker](https://developer.mozilla.org/en-US/docs/Web/API/Service_Worker_API) (a script the browser runs in the background, between the page and the network, so the app can serve cached content and receive push messages even when no tab is open). Together they let HealthLog install to the home screen and behave like a native app without an app store.

## Installation

HealthLog can be installed as a standalone app on mobile and desktop:

- **Android** -- "Add to Home Screen" via Chrome or any Chromium-based browser.
- **iOS** -- "Add to Home Screen" via Safari (Share menu).
- **Desktop** -- Install prompt in Chrome, Edge, or other supported browsers.

Once installed, the app launches in standalone mode without browser UI (address bar, tabs) — this is driven by the manifest's `display: standalone` member. It behaves like a native application.

## Service Worker Caching

The [service worker](https://developer.mozilla.org/en-US/docs/Web/API/Service_Worker_API) sits between the app and the network and decides, per request, whether to answer from the [Cache API](https://developer.mozilla.org/en-US/docs/Web/API/Cache) (the browser's persistent store of request/response pairs) or to go to the server. It uses different caching strategies depending on the resource type:

| Resource Type | Strategy | Rationale |
|---------------|----------|-----------|
| Static assets (JS, CSS, images, fonts) | Cache-first | Immutable after build, served instantly from cache |
| HTML pages | Network-first | Always attempt to load the latest version, fall back to cache if offline |
| API requests (`/api/*`) | Network-only | Data must always be fresh, no stale API responses |

:::note
API requests are never cached. If the device is offline, API calls will fail gracefully and the UI displays appropriate offline indicators.
:::

:::note
The PWA does not maintain its own offline write store — it reads live or shows an offline indicator. Native clients (the iOS app) that hold a local copy keep it current through the [offline sync contract](/api/sync/) (`/api/sync/changes`), which carries incremental upserts and soft-delete tombstones since the last cursor.
:::

### Cache Lifecycle

The service worker has a defined lifecycle — `install`, then `activate` — and HealthLog hooks both to keep the cache fresh:

- Static assets are precached during the service worker's `install` event.
- The named page cache is updated on each successful network fetch.
- Old, version-stamped caches are purged automatically when a new service worker `activate`s, so a deploy never serves a mix of old and new assets.

## iOS Safe Area Support

HealthLog accounts for device notches, rounded corners, and home indicators on modern iOS devices:

- The viewport is configured with `viewport-fit: cover` to extend content to the full screen.
- CSS environment variables handle safe area insets:

```css
padding-bottom: env(safe-area-inset-bottom);
padding-top: env(safe-area-inset-top);
padding-left: env(safe-area-inset-left);
padding-right: env(safe-area-inset-right);
```

:::tip
The bottom navigation bar automatically respects `env(safe-area-inset-bottom)` so that buttons remain tappable on devices with a home indicator (iPhone X and later).
:::

## Web Push Notifications

HealthLog supports browser-based push notifications via the [Push API](https://developer.mozilla.org/en-US/docs/Web/API/Push_API) — the standard that lets the service worker receive a message from the server and show a notification even when no tab is open. Delivery is authenticated with [VAPID](https://datatracker.ietf.org/doc/html/rfc8292) (Voluntary Application Server Identification, RFC 8292), a signed token that identifies your HealthLog server to the browser's push service so only your instance can push to your subscribers.

### Setup

1. Generate VAPID keys or configure them in the admin panel under **Admin → Services** (`/admin/services`).
2. Users subscribe to push notifications from their profile settings.
3. Subscriptions are device-specific -- a user can have multiple active subscriptions.

### How It Works

- Push notifications are sent server-side using the Web Push protocol.
- Notifications are delivered even when the browser tab is closed or the PWA is not in the foreground.
- Supported events: medication reminders, measurement anomalies, compliance alerts, and system notifications.

:::caution
Web Push requires HTTPS and valid VAPID keys. On iOS, push notifications for PWAs require iOS 16.4 or later and the app must be installed to the home screen.
:::

See [Notifications](/features/notifications/) for details on all notification channels and event types.
