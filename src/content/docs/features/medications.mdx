Medication management is the core of HealthLog. It covers medication tracking, a flexible recurrence engine, a phased reminder system, and cadence-aware [medication-adherence](https://en.wikipedia.org/wiki/Adherence_(medicine)) analytics — adherence being the degree to which doses are actually taken as prescribed, which is what the compliance figures below measure.

## Adding Medications

Each medication is defined with the following attributes:

- **Name** — Free-text field
- **Dose** — Default dose (e.g. "10mg")
- **Route of administration** — `ORAL`, `INJECTION`, or `OTHER`. Injections add injection-site tracking so the rotation can be logged.
- **Category** — User-defined categories for grouping
- **Course window** — Optional `startsOn` / `endsOn` dates. `endsOn` left empty means a chronic (open-ended) medication.
- **Active/Inactive** — Only active medications generate reminders

## Schedules

A schedule says *when* a dose is due. Rather than a flat time window, schedules are projected by a canonical recurrence engine that all reads share — the dashboard tile, the detail page, the reminder worker, and compliance all expand the same rule, so they never disagree.

A schedule combines two things: the **times of day** the dose is taken, and the **recurrence** that decides which days are "due".

```typescript
interface MedicationSchedule {
  timesOfDay: string[];          // e.g. ["08:00", "20:00"] — up to 8 points per day
  label?: string;                // e.g. "Morning", "Evening"
  dose?: string;                 // Optional: overrides the default dose
  reminderGraceMinutes?: number; // How long past the time a dose still counts as on-time

  // Recurrence — pick the one that fits (rrule and rollingIntervalDays are mutually exclusive):
  rrule?: string;                // RFC 5545 RRULE, e.g. "FREQ=WEEKLY;INTERVAL=2;BYDAY=WE"
  rollingIntervalDays?: number;  // Re-anchors from the last logged dose, 1..365

  scheduleType?: "SCHEDULED" | "PRN" | "CYCLIC";
  cyclicOnWeeks?: number;        // CYCLIC only: weeks "on"
  cyclicOffWeeks?: number;       // CYCLIC only: weeks "off"
}
```

### Recurrence options

| Cadence | How to express it |
|---|---|
| **Daily** | `rrule: "FREQ=DAILY"` (the default if no recurrence is given) |
| **Specific weekdays** | `rrule: "FREQ=WEEKLY;BYDAY=MO,WE,FR"` |
| **Bi-weekly / multi-week** | `rrule: "FREQ=WEEKLY;INTERVAL=2;BYDAY=WE"` |
| **Monthly / yearly** | `rrule: "FREQ=MONTHLY;BYMONTHDAY=1"`, `rrule: "FREQ=YEARLY;BYMONTH=1;BYMONTHDAY=1"` |
| **Rolling** | `rollingIntervalDays: 84` — the next dose is N days after the *last logged* dose, not a fixed calendar grid (e.g. a 12-week injection) |
| **One-time** | a single schedule with no recurrence on a medication created with `oneShot: true` — the medication auto-deactivates once the dose is logged (flu shot, post-op single dose) |
| **As-needed (PRN)** | `scheduleType: "PRN"` — never projected, reminded, or counted in compliance, but still loggable |
| **Cyclic on/off** | `scheduleType: "CYCLIC"` with `cyclicOnWeeks` / `cyclicOffWeeks` — N weeks of the inner cadence, then M weeks off |

The `rrule` string is a subset of the [RFC 5545 recurrence rule](https://datatracker.ietf.org/doc/html/rfc5545#section-3.3.10) format (the same grammar calendar apps use for repeating events), so cadences stay portable and interoperable. `rrule` and `rollingIntervalDays` are mutually exclusive — supplying both is rejected (`rrule_xor_rolling`), and the database enforces the same invariant with a `CHECK` constraint.

:::note
`windowStart` / `windowEnd` / `daysOfWeek` / `intervalWeeks` are legacy fields preserved for older clients. New schedules express the same intent through `timesOfDay` + `rrule`. Readers consult `rrule` first and fall back to the legacy fields only when no rule is present.
:::

### Next-due instant

Every medication carries a read-only **`nextDueAt`** — the server computes the next scheduled instant from the recurrence (RFC 5545 plus rolling math) so a client never has to re-implement the engine. It is `null` for PRN schedules, which have no projected due time.

:::tip
For medications with varying doses on different days (e.g. methotrexate), create multiple schedules with different recurrences and dose overrides.
:::

## Intake Tracking

Intakes are recorded with idempotency protection: duplicate entries for the same schedule within 60 seconds are automatically prevented.

### Intake Sources

| Source | Description |
|--------|------------|
| `WEB` | Manually via the web interface |
| `API` | Via the external API (Bearer token) |
| `REMINDER` | Via inline buttons in notifications |
| `IMPORT` | From a JSON import |

## Phase-Based Reminders

The reminder system uses four phases, signaled both visually and via notifications:

| Phase | Color | Meaning |
|-------|-------|---------|
| GREEN | Green | Time window has started -- intake now possible |
| YELLOW | Yellow | Time window ending soon -- reminder |
| ORANGE | Orange | Time window exceeded -- overdue |
| RED | Red | Intake missed -- marked as missed |

### Phase Configuration

Phase transitions are configurable **per medication**:

- **Minutes** -- Fixed time value (e.g., 15 minutes before the window ends)
- **Percent** -- Percentage of the time window (e.g., 80% of the window elapsed)

:::note
The default configuration works well for most cases. Custom adjustments are particularly useful for very short or very long time windows.
:::

## Compliance Analytics

HealthLog calculates compliance rates at three levels:

- **7-day rate** — Short-term adherence
- **30-day rate** — Monthly compliance
- **90-day heatmap** — Visual overview of adherence over three months

The heatmap uses colour coding to show whether all doses were taken, partially taken, or missed for each day.

Compliance is **cadence-aware**: the denominator counts only the doses actually due, projected through the same recurrence engine the schedule uses. A bi-weekly, rolling, RRULE, or cyclic plan is never penalised for the days it was never due, and PRN doses are excluded from the expected count entirely. The per-day compliance payload exposes `due` and `expectedCount`, so a history view can skip empty marks on non-due days instead of painting them as misses. The dashboard tile and the detail page route through the same calculation, so they agree for every cadence.

## Pause / Snooze

- **Pause**: Suspends all reminders for a medication (e.g., while consulting a doctor)
- **Snooze**: Postpones a single reminder by a configurable duration

## Categories

Medications can be organized into user-defined categories. Categories help keep the dashboard organized and serve as filters in the compliance analytics.
