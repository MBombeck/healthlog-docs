HealthLog offers AI-powered analysis of your health data. As of v1.2 you can pick the provider that fits your privacy and budget profile — there is no longer a single hard-coded vendor.

## Providers

Configure a provider per user under **Settings → AI**:

| Provider | Setup | Notes |
|----------|-------|-------|
| **OpenAI** | Paste your own API key (BYOK), or use the admin-shared key | Model dropdown with provider presets, plus a custom-model field for power users |
| **Anthropic Claude** | Paste your API key | Examples: `claude-3-5-haiku`, `claude-3-5-sonnet` |
| **ChatGPT subscription (Codex)** | One-click **Connect with ChatGPT** — runs entirely through your existing ChatGPT Plus / Pro subscription, no API plan or separate billing required | Uses the OpenAI device-code flow (the same mechanism the official Codex CLI uses for headless / hosted environments). Requires the operator to set `CODEX_OAUTH_CLIENT_ID`; otherwise the button is hidden and the API-key path is the only route |
| **Local / OpenAI-compatible** | Custom base URL + optional API key | Ollama, LM Studio, vLLM, LiteLLM — your data never leaves your network |

Selection is per user. Switching providers stores the new credentials and clears any provider-specific URL the previous selection had set, so a saved local URL cannot leak to OpenAI / Anthropic on the next request.

## Setup

Pick a provider, paste the API key (and base URL for local endpoints), and pick a model from the dropdown. Keys and URLs are stored AES-256-GCM encrypted in the database. The **Test connection** button fires a single low-cost request and surfaces a clean error message if the key, model, or URL is wrong.

## Connect with ChatGPT (v1.4.14)

The ChatGPT-subscription path lets you reuse the GPT capacity that ships with ChatGPT Plus or Pro — no separate OpenAI API plan, no second invoice. HealthLog talks to the same `chatgpt.com/backend-api/codex/responses` endpoint that the official Codex CLI uses, with the access token issued for your ChatGPT account.

**How the flow works:**

1. Open **Settings → AI**, pick **ChatGPT (Codex)**, click **Connect with ChatGPT**.
2. HealthLog displays a short user code (e.g. `RGRP-N5F7U`) and opens `https://auth.openai.com/codex/device` in a new tab.
3. Enter the code on that page, confirm the access prompt with your ChatGPT account.
4. The Settings panel polls in the background and switches to **ChatGPT connected** — done.

There is no redirect URL to whitelist, so the flow works on any HealthLog instance, including hosted self-hosts behind a domain. The OAuth refresh token is stored AES-256-GCM encrypted; HealthLog rotates the access token transparently before each request.

**Default model.** The default is `gpt-5.3-codex` — the codex-optimised slug that ChatGPT Plus and Pro tiers can call. Operators can pin a different default for their plan tier via the `CODEX_MODEL` environment variable (for example, a Pro-only slug). The Codex backend rejects model slugs that aren't in the allow-list for your plan with a clear error message in **Test connection**.

**Disconnect.** A **Disconnect** button next to the badge revokes the stored token; reconnect any time.

:::note
If you connected before v1.4.14, click **Disconnect** and reconnect once. The earlier storage form did not carry the `chatgpt_account_id` claim that the Codex backend requires today, so old tokens cannot be carried forward.
:::

:::note
Without any provider configured, AI Insights are disabled. Every other HealthLog feature stays fully functional, and the dashboard simply hides the AI cards.
:::

## Inline Charts in Findings (v1.4+)

When the model identifies a metric-specific finding, it can embed a chart token that renders the matching chart directly under the paragraph. Supported tokens include `metric:WEIGHT`, `metric:BLOOD_PRESSURE`, `metric:PULSE`, `metric:BMI`, `metric:MOOD`, and the medication-compliance chart. The renderer is allow-listed server-side — only the supported tokens render; any other emission is dropped silently. The "Key Takeaway" card strips the tokens for prose and renders the matching chart underneath.

## Evidence-Anchored Findings (v1.4.3+)

Every finding must cite a concrete number ("138/85 mmHg", "+0.4 mmol/L vs 30d-avg") rather than adjectives. Findings without a measurement anchor are dropped. Generic boilerplate ("drink enough water", "consult your doctor") is forbidden outside the disclaimer.

## Prompt Tone (v1.4.19)

v1.4.19 revises the system prompt so insights no longer open with a default-positivity sentence about data quality. "Your data foundation is strong" / "Datengrundlage ist sehr stark" openers are explicitly forbidden by GROUND RULE 7 in both EN and DE locales. Data-quality caveats are still allowed when they're useful — `n < 7` in the analysed window, recency older than 14 days, or a coverage gap that biases the comparison — but they no longer pad every reply. `PROMPT_VERSION` bumped 4.16.1 → 4.19.0 so feedback aggregation can attribute responses to the new rule.

## Daily Briefing, AI Coach, and Health Score (v1.4.20)

v1.4.20 ships a redesigned `/insights` surface that mounts five new pieces on top of the existing recommendation engine.

- **Daily Briefing** — a short paragraph plus three keyFindings drawn from the last 24-hour window, generated alongside the regular insight payload. It anchors the page so you have something opinionated to read every time you open Insights, even on quiet days.
- **AI Coach drawer** — a right-side drawer that hosts a streaming chat. The Coach has the same provider configuration as the rest of Insights, walks the same fallback chain, and runs every reply through the same evidence-grounded schema. Conversations persist across sessions, encrypted at rest with AES-256-GCM. Source-chip provenance attaches to every assistant turn (metric, window, n-count — labels only, never raw values), so you can tell at a glance which slice of your data each answer drew on. A per-user daily token budget (25 000 tokens, ≈13 turns for a heavy user) prevents runaway spend on shared provider keys; a prompt-injection refusal pattern blocks obvious off-topic asks before the provider call.
- **Suggested-prompt chips** — six starter questions on the hero strip (e.g. *Why is my BP higher this week?*, *How is my mood trending?*) that open the Coach drawer with the prompt prefilled.
- **Personal Health Score** — a deterministic composite 0–100 score with three bands (green ≥75, yellow 50–74, red &lt;50). Weights: 30% BP-target rate, 20% weight-trend alignment, 20% mood stability, 30% medication compliance. The Score panel sits beside the hero strip on `lg+` and includes an "Ask the Coach" CTA that opens the drawer with a score-aware prefill.
- **Weekly Report** — a printable newsletter-style page at `/insights/report/[week]` (Summary / Going-well / Worth-watching / Tips / Data-quality). The hero surfaces fresh reports with Read · Share · Export PDF actions; export uses `window.print()` against Tailwind `print:` variants, so you get a clean A4 page without a server round-trip.

Three pre-defined correlation cards (BP × medication compliance, mood × pulse, weight × weekday) and a Trends row with AI annotations on the BP timeline round out the new layout. `PROMPT_VERSION` ratcheted 4.19.0 → 4.20.0 → 4.20.1 → 4.20.2 across the rollout; every bump carries one new optional schema block, so insights cached before v1.4.20 still parse without a re-run.

## Hardened Guardrails (v1.4.15+)

v1.4.15 tightens the contract between HealthLog and the model. Every recommendation must cite a concrete data point from the snapshot you submitted; recommendations that try to cite anything that isn't in the snapshot are rejected before they reach you. If the model returns a malformed response, HealthLog corrects it and re-asks once; if the second attempt still fails, you get a clean error rather than a half-broken card. The system prompt is versioned (the `PROMPT_VERSION` field in the audit log records which prompt produced which response), and on the ChatGPT-via-Codex path the model slug is auto-failed-over through a configurable fallback chain so a vendor-side rotation doesn't silently break Insights. The AI is still informational only — the disclaimer footer stays — but it can no longer make up numbers.

## Per-Recommendation Explainability (v1.4.16+)

Every recommendation now carries a **rationale** that explains where it came from. Click the chevron on a card to expand it and you see three lines plus a mini-chart of the data window the model actually looked at:

- **Window** — the time range the recommendation was derived from (e.g. *last 30 days*, *last 7 days*).
- **Compared to** — the baseline the current value was checked against (your 90-day personal baseline, the prior period, the guideline target).
- **Deviation** — what the difference looked like in plain numbers (e.g. *+6 mmHg systolic vs. last month*).

The mini-chart embedded directly under the rationale is the same Recharts wrapper that powers the dashboard, scoped to the rationale window — you see the same data the model saw, in 140 px of vertical space. If the chart series doesn't match the metric the recommendation talks about, that's a schema violation and the recommendation is rejected before it reaches you.

The rationale is part of the strict schema. A recommendation without `dataWindow`, `comparedTo`, and `deviation` won't render — the corrective retry runs first; if the model still won't comply, the recommendation is dropped.

## Confidence Score (v1.4.16+)

Every recommendation gets a **0–100 confidence score** that's computed deterministically on the server, not whatever the model claims. The score is derived from three inputs:

- **Sample size** — how many readings backed the finding. Log-saturating; capped at 40 points. Fewer than three readings hard-caps the score at `5 × n`.
- **Recency** — how stale the most recent reading was. Linear decay, 30 points at zero days down to zero at 30 days old.
- **Signal strength** — the magnitude of the deviation in standard deviations. 30 points at \|z\| ≥ 1.5; null signal contributes a neutral 15.

The card renders the score as a colour-banded ring + 5-bar meter on the right of the recommendation. Scores below 25 show a small "Low confidence — based on limited data" pill instead of being hidden, so you can still see the suggestion and decide for yourself whether to act on it. The model's claimed confidence value is discarded — the meter you see is always the deterministic computation.

## Was-this-helpful Feedback (v1.4.16+)

Every recommendation has a **thumbs-up / thumbs-down** pair. Tapping a thumb is optimistic — the UI updates immediately, the mutation persists in the background. Each verdict is stored against `(userId, recommendationId, recommendationText)`, so toggling within the same recommendation overwrites the previous vote and you can't double-count yourself.

Provider attribution is **filled server-side** from the latest insight-generation audit row — clients can't tamper with which provider gets credit. The feedback table ties feedback to the provider that produced the recommendation, so the admin AI-quality dashboard at `/admin/ai-quality` can show per-(severity × provider) helpful-rate over time.

Privacy: feedback is **per-user only**. The aggregate is admin-only and gated behind `requireAdmin`. Cross-user feedback never leaves your instance, and the daily aggregator only writes summary counts, not individual votes.

## Medical-Reference Grounding (v1.4.16+)

Recommendations now cite **curated medical guidelines** by id. The bundle ships with seven references — ESH 2023, ESC 2024, ACC/AHA 2017, WHO 2021 hypertension, WHO BMI, DGE 2024 nutrition, AHA pulse — each with a stable slug, EN/DE titles, the source URL, and the metrics it applies to.

The system prompt injects a SOURCES block listing only references that match the metrics in the current snapshot, plus a ground rule telling the model to cite by id. The schema validates the `referenceId` field against the bundle — a fabricated id fails parse before it can render. The post-validation step logs **citation coverage** (how many normative recommendations carry a citation) as a Wide-Event annotation, so the admin AI-quality dashboard can plot coverage over time.

In the UI, every cited recommendation gets a small "Source: ESH 2023" footnote with an external-link icon. Click it and the source guideline opens in a new tab. No model hallucinations of "studies have shown…" — if a recommendation makes a normative claim, it cites a guideline you can read for yourself.

## Multi-Provider Fallback Chain (v1.4.16+)

The insight wrapper tries each configured provider in turn. If a provider hard-fails — `401`, `403`, `429`, `5xx`, transport error — the wrapper cascades to the next. **Schema 422** still bubbles, because that's a problem with the response body, not the provider; retrying it against another provider would just waste another paid request. The last provider that successfully answered is **cached for an hour** per user, so the cascade only runs once after a vendor outage instead of on every generation.

Order, enable / disable, and the provider list itself are configurable per user under **Settings → AI**. See [Provider configuration](/settings/ai-providers/) for the dropdown + form layout, the test-connection button, and the fallback chain editor.

The chain is **per user**, not per instance — you can have one user on Codex with OpenAI fallback, another user on a local Ollama with no fallback, and a third user on the admin-shared OpenAI key. The "active provider" badge in Settings → AI shows which entry actually answered the most recent generation, so you can see at a glance whether the fallback kicked in.

For a deeper walk-through of how the rationale, confidence, citations, and feedback all fit together end-to-end, see [How AI Insights work](/insights/how-it-works/).

## Three Years of Context (v1.4.6)

Every per-card insight (general, blood pressure, pulse, weight, BMI, mood, medication compliance) sees up to 360 daily means plus 24 monthly means for the older window — three years of history per metric — so the model can spot drift that plays out over a year, not just over the last 30 days. A 50 KB safety guard re-buckets at 180 daily days for particularly noisy accounts so the prompt token budget never blows out.

## Privacy Modes

Users choose what data is sent to the provider:

| Mode | Description |
|------|------------|
| **Aggregated** | Only statistical summaries (average, min, max, trend) |
| **Raw** | Actual readings with timestamps |

:::caution
In Raw mode, real health data is sent to the configured provider. Local endpoints keep the data on your network; cloud providers see whatever you send.
:::

## Insight Categories

HealthLog generates insights across seven categories:

1. **General** — Cross-domain synthesis with cardiovascular risk stratification
2. **Blood Pressure** — Trend, ESH 2023 classification, morning risk, pulse pressure
3. **Weight** — Trend, BMI, plateau detection, body-composition divergence
4. **Heart Rate** — Resting trends, fitness ladder, anomalies
5. **BMI** — Long-term development, age-adjusted DEGAM bands for 65+
6. **Medication Compliance** — Adherence, chronotherapy hints, mood-adherence risk
7. **Mood** — Mood trends, bidirectional correlations with vitals and adherence

## Caching and Generation

- **Cache duration**: 24 hours per insight
- **Automatic generation**: Nightly between 02:00 and 02:30 (pg-boss cron)
- **Manual generation**: Available anytime from the dashboard (invalidates the cache)
- **Rate limit**: 10 generations per hour per user (v1.4.16+; previously 2/h). Configurable via the `INSIGHTS_RATE_LIMIT_PER_HOUR` env var.
- **Cached reloads** do not consume rate-limit budget — a noisy refresh from the dashboard cannot lock you out of fresh generations.
- **Regeneration evicts the cache fully** (v1.4.16+) — when you generate a new insight, every previously cached per-status payload for that user is deleted, so the dashboard never shows a stale cached card next to a fresh one.

## Locale-Aware Prompts

Prompts and responses run in the user's selected locale. A German user gets German recommendations; an English user gets English. Numbers, dates, and units (mg/dL vs mmol/L, kg, mmHg) are formatted by `useFormatters()` before being injected into the prompt — the model never has to translate or convert.

:::tip
Even without an AI provider, HealthLog provides detailed statistics, trend analysis, and reference-range comparisons on the dashboard. The AI is additive, not load-bearing.
:::
