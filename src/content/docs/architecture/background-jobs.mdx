HealthLog uses [**pg-boss v12**](https://github.com/timgit/pg-boss) for background jobs — a [job queue](https://en.wikipedia.org/wiki/Job_queue) that schedules and runs work outside the request/response cycle (sending reminders, pre-computing insights, taking backups). pg-boss stores its jobs directly in PostgreSQL using `SKIP LOCKED` row-level locking — no separate message broker (Redis, RabbitMQ) needed, which keeps a self-hosted instance to a single moving part.

## Worker Startup

The worker starts automatically via the **Next.js Instrumentation API** (`register()`). On server startup, pg-boss is initialized and all cron jobs are registered. No manual startup is required.

The health check endpoint `/api/health` returns the current worker status.

## Job Overview

Recurring jobs are scheduled with [cron expressions](https://en.wikipedia.org/wiki/Cron) — the familiar five-field `minute hour day month weekday` syntax. Every schedule below runs in the **Europe/Berlin** timezone, not UTC.

The instance registers roughly three dozen recurring queues. The representative set below is grouped by purpose; the canonical list lives in `src/lib/jobs/reminder-worker.ts`.

## Medication Reminders

The `medication-reminder-check` job runs every 15 minutes and checks for each user:

1. **Due reminders** — Scheduled intakes without confirmation, phase escalation (gentle, urgent, missed)
2. **Snooze expiry** — Expired snooze timers reactivate the reminder
3. **Message cleanup** — Deletes outdated Telegram reminder messages

Escalation phases and thresholds are controlled through `ReminderPhaseConfig` (per medication) and the admin settings (`reminderLateMinutes`, `reminderMissedMinutes`).

## Insights Jobs

The per-metric insight-status jobs run staggered between 02:00 and 02:25 Europe/Berlin to avoid overloading the database with concurrent queries. Each job calculates trends, averages, and anomalies for its respective measurement type. The server-derived score jobs (`recovery-score`, `stress-score`, `strain-score`) run later in the 04:45–04:55 window, after the nightly rollup and consolidation passes have folded the signals they read.

A separate **`insight-pregenerate`** job runs nightly at 04:30 Europe/Berlin. It is budget-gated and warms the comprehensive AI insight and the daily briefing, so opening `/insights` is a cache read instead of a synchronous model call. The unified [dashboard snapshot](/features/dashboard-customization/#first-paint-snapshot--nightly-pre-generation) reads that pre-generated briefing for its first paint.

## Data Backup

The weekly backup job creates an encrypted export of all user data. Metadata is stored in the `DataBackup` model.

## Error Handling

pg-boss provides built-in retry behavior. Failed jobs are retried with exponential backoff. Persistent failures are logged and recorded in the audit log.
