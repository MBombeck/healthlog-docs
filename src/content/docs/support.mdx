title: Support and contact
description: Get help with HealthLog, report a bug, ask a usage question, or contact the project privately about security and privacy.
---

HealthLog support is maintained through the public project channels below.
Choose the channel that matches the information you need to share.

## Report an app or server bug

Use the [HealthLog bug-report form](https://github.com/MBombeck/HealthLog/issues/new?template=bug_report.yml)
for reproducible problems in the iOS app or self-hosted server. Search the
[existing issues](https://github.com/MBombeck/HealthLog/issues) first.

Include:

- the HealthLog version (the server reports it at `/api/version`);
- the device model and operating-system version for an app problem;
- the affected screen or server route;
- exact steps to reproduce the problem; and
- the error class or request ID, if one is shown.

Do not include real health information, account identifiers, access tokens,
API keys, server credentials, or unredacted logs and screenshots in a public
issue. Use synthetic values and remove identifying metadata from attachments.

## Ask a usage or configuration question

Use [GitHub Discussions](https://github.com/MBombeck/HealthLog/discussions) for
setup questions, self-hosting help, and ideas that are not confirmed bugs. A
self-hosted instance is operated by its own administrator, so questions about
its availability, backups, accounts, or configured integrations should first
go to that administrator.

## Privacy and account requests

Do not put an account-deletion, access, portability, or other privacy request in
a public issue. The hosted instance's bilingual
[privacy policy](https://healthlog.bombeck.io/privacy#contact) provides its
maintained private contact route. A different self-hosted instance has its own
controller and contact policy.

An account can also be deleted directly in HealthLog's account settings. When
the account has a second factor enrolled, the deletion asks for a fresh
identity check first.

## Report a security vulnerability

Do not disclose a vulnerability in a public issue or discussion. Use
[GitHub's private security-advisory form](https://github.com/MBombeck/HealthLog/security/advisories/new)
and follow the project's
[security policy](https://github.com/MBombeck/HealthLog/blob/main/SECURITY.md).
Never attach production credentials or real health records to a report.

## Deutsch

Fehler in App oder Server bitte über das
[Bug-Formular](https://github.com/MBombeck/HealthLog/issues/new?template=bug_report.yml)
melden; allgemeine Fragen gehören in die
[Diskussionen](https://github.com/MBombeck/HealthLog/discussions). In
öffentlichen Beiträgen niemals echte Gesundheitsdaten, Konto-Kennungen,
Zugangsdaten, API-Schlüssel oder unbereinigte Logs und Screenshots teilen.
Datenschutz- und Kontoanfragen verwenden den privaten Kontaktweg der
[Datenschutzerklärung](https://healthlog.bombeck.io/privacy#contact),
Sicherheitslücken ausschließlich die
[private Sicherheitsmeldung](https://github.com/MBombeck/HealthLog/security/advisories/new).
