HealthLog is configured through environment variables. Place them in a `.env` file next to your `docker-compose.yml`. The canonical, always-current reference ships in the repo as [`.env.example`](https://github.com/MBombeck/HealthLog/blob/main/.env.example); a production-shaped variant lives in [`.env.production.example`](https://github.com/MBombeck/HealthLog/blob/main/.env.production.example). The `pnpm check-env` tool reads [`scripts/env-manifest.json`](https://github.com/MBombeck/HealthLog/blob/main/scripts/env-manifest.json) and verifies that every required variable is set before a deploy ships.

## Required

These variables **must** be set for HealthLog to start — the container entrypoint refuses to boot without `DATABASE_URL`, `ENCRYPTION_KEY`, and `API_TOKEN_HMAC_KEY`.

| Variable | Description | Example |
|---|---|---|
| `DATABASE_URL` | [PostgreSQL](https://www.postgresql.org/docs/) connection string. With the bundled compose stack the hostname is the `db` service, not `localhost`. | `postgresql://healthlog:<pw>@db:5432/healthlog?schema=public` |
| `POSTGRES_PASSWORD` | Password for the bundled `db` service in `docker-compose.yml`; reuse it inside `DATABASE_URL`. | `openssl rand -base64 24` |
| `ENCRYPTION_KEY` | [AES-256-GCM](https://en.wikipedia.org/wiki/Galois/Counter_Mode) key for at-rest encryption of provider tokens. 64 hex characters (32 bytes). Required unless `ENCRYPTION_KEYS` is set. | `openssl rand -hex 32` |
| `API_TOKEN_HMAC_KEY` | [HMAC](https://en.wikipedia.org/wiki/HMAC)-SHA-256 key for hashing external Bearer tokens before storage. 64 hex characters. | `openssl rand -hex 32` |

:::danger
`ENCRYPTION_KEY` must **never** be changed after the initial startup. All encrypted database fields (tokens, OAuth credentials, API keys) are encrypted and decrypted with this key. Changing it makes all encrypted data permanently unrecoverable. For a planned rotation, use the versioned `ENCRYPTION_KEYS` map and the rotation script — see [Scaling & Operations](/self-hosting/scaling/).
:::

:::note
There is **no** `SESSION_SECRET`. HealthLog authenticates with [Passkeys](https://en.wikipedia.org/wiki/WebAuthn) (WebAuthn) and stores sessions server-side in PostgreSQL, so there is no stateless session-signing secret to configure or leak — see the [database schema](/architecture/database/#why-sessions-live-in-postgres) for why.
:::

## App URL

| Variable | Description | Example |
|---|---|---|
| `NEXT_PUBLIC_APP_URL` | Public URL of the app. Used for the passkey RP-ID, OAuth redirects, webhook callbacks, and APNs deep-links. | `https://health.example.com` |
| `APP_URL` | Server-side mirror of `NEXT_PUBLIC_APP_URL`, read by background workers. | `https://health.example.com` |
| `NODE_ENV` | `production` or `development`. | `production` |
| `SESSION_COOKIE_SECURE` | Overrides the session-cookie `Secure` flag. Defaults to `NODE_ENV === "production"`. Set to `false` only when you intentionally serve plain HTTP on a LAN / VPN / Tailscale surface — never on the open internet. | `false` |

| Variable | Description |

## Withings

Register an app at [developer.withings.com](https://developer.withings.com/). The OAuth client id/secret can also be set per-user in Settings.

| Variable | Description |
|---|---|
| `WITHINGS_CLIENT_ID` / `WITHINGS_CLIENT_SECRET` | Instance-wide [OAuth 2.0](https://datatracker.ietf.org/doc/html/rfc6749) credentials (optional — per-user values in Settings override). |
| `WITHINGS_REDIRECT_URI` | Optional override for the OAuth redirect URI (defaults to `${NEXT_PUBLIC_APP_URL}/api/withings/callback`). |
| `WITHINGS_WEBHOOK_SECRET` | Secret carried as a path segment in the webhook callback URL to harden it. |

## WHOOP

The WHOOP client id/secret are **per-user BYO keys** (each user registers their own WHOOP developer app and pastes the credentials into Settings, stored encrypted) — there is therefore no `WHOOP_CLIENT_ID` / `WHOOP_CLIENT_SECRET`.

| Variable | Description |
|---|---|
| `WHOOP_WEBHOOK_SECRET` | Instance-level secret carried as the trailing path segment of the webhook URL and used to verify the WHOOP HMAC body signature. |
| `WHOOP_REDIRECT_URI` | Optional override for the derived `${NEXT_PUBLIC_APP_URL}/api/whoop/callback`. |

## Fitbit / Google Health (experimental)

The Fitbit OAuth client is a per-user BYO key configured in Settings.

| Variable | Description |
|---|---|
| `FITBIT_REDIRECT_URI` | Optional override for the derived Fitbit OAuth callback URL. |

## AI providers

Users bring their own API keys via Settings; no server-side key is needed by default. The admin can configure a fallback key in the admin panel.

| Variable | Description | Default |
|---|---|---|
| `CODEX_OAUTH_CLIENT_ID` | When set, the **Connect with ChatGPT** button appears in Settings → AI and the [OAuth 2.0 device-authorization flow](https://datatracker.ietf.org/doc/html/rfc8628) against `auth.openai.com` is enabled. Without it the API-key path is the only route. | — |
| `CODEX_MODEL` | Pins a specific model slug at the head of the ChatGPT-Codex fallback chain. Leave unset to use the built-in chain (currently led by the latest GPT slug accepted by your plan). | — |
| `CODEX_MODEL_FALLBACK_CHAIN` | Comma-separated override of the entire Codex slug fallback order. The client walks the chain so a single upstream allow-list rotation does not brick the integration. | built-in chain |
| `ALLOW_LOCAL_AI_PRIVATE_HOSTS` | Set to `true` to let the local-LLM base URL resolve to a private/loopback host. The default blocks private addresses as an [SSRF](https://owasp.org/www-community/attacks/Server_Side_Request_Forgery) guard; only enable it for a trusted on-LAN Ollama/LM-Studio endpoint. | — |
| `ADMIN_AI_BASE_URL_ALLOWLIST` | Comma-separated allow-list of hostnames the admin may set as a custom AI base URL, narrowing the SSRF surface further. | — |
| `INSIGHTS_RATE_LIMIT_PER_HOUR` | Maximum comprehensive-insight generations a single user can trigger per hour (`POST /api/insights/generate`). The 24 h DB cache short-circuits read traffic; only forced or expired-cache regenerations consume tokens. | `10` |

## Web Push (fallback)

These are optional — Web Push (VAPID) can also be configured through admin settings, which take precedence. The code accepts several historical aliases for each value; pick one per slot.

| Variable | Description |
|---|---|
| `VAPID_PUBLIC_KEY` / `NEXT_PUBLIC_VAPID_PUBLIC_KEY` / `WEB_PUSH_VAPID_PUBLIC_KEY` / `WEB_PUSH_PUBLIC_KEY` | [VAPID](https://datatracker.ietf.org/doc/html/rfc8292) public key for [Web Push](https://developer.mozilla.org/en-US/docs/Web/API/Push_API). |
| `VAPID_PRIVATE_KEY` / `WEB_PUSH_VAPID_PRIVATE_KEY` / `WEB_PUSH_PRIVATE_KEY` | VAPID private key. |
| `VAPID_SUBJECT` / `WEB_PUSH_VAPID_SUBJECT` / `WEB_PUSH_SUBJECT` | Contact URI for VAPID (`mailto:admin@example.com`). |

## APNs — Apple Push Notification service

All four core `APNS_*` vars must be set **together** for APNs to fan out to iOS devices; missing any disables the channel silently (the dispatcher falls back to Telegram → ntfy → Web Push). Provision an APNs auth key (`.p8`) in the [Apple Developer](https://developer.apple.com/account/) portal.

| Variable | Description |
|---|---|
| `APNS_KEY_ID` | 10-char Key ID from Apple Developer. |
| `APNS_TEAM_ID` | 10-char Team ID from Apple Developer. |
| `APNS_BUNDLE_ID` | iOS app bundle id (e.g. `dev.healthlog.ios`). |
| `APNS_KEY` **or** `APNS_KEY_FILE` | The `.p8` body (PEM, `\n` escapes accepted) **or** a filesystem path to it — at least one is required. |
| `APNS_PRODUCTION` | `true` to force the production gateway; default mirrors each `Device.apnsEnvironment`. |

## Encryption-key versioning (rotation)

| Variable | Description |
|---|---|
| `ENCRYPTION_KEYS` | JSON map of key id → 64-hex / base64 32-byte key, e.g. `{"v1":"<old>","v2":"<new>"}`. Supersedes `ENCRYPTION_KEY` for new writes; old rows decrypt under their original id. |
| `ENCRYPTION_ACTIVE_KEY_ID` | Which entry in `ENCRYPTION_KEYS` encrypts new writes. |

See [Scaling & Operations](/self-hosting/scaling/) for the `rotate-encryption-key.ts` workflow.

## Process split (scaling)

| Variable | Description | Default |
|---|---|---|
| `HEALTHLOG_PROCESS_TYPE` | `all` (HTTP + pg-boss worker in one container), `web` (HTTP only), or `worker` (pg-boss only; rejects HTTP with 503). | `all` |

## Off-host S3 backups

Required **all-or-none**: setting any of these without the rest disables the backup silently. The names map 1:1 to [`.env.example`](https://github.com/MBombeck/HealthLog/blob/main/.env.example).

| Variable | Description | Default |
|---|---|---|
| `BACKUP_S3_ENDPOINT` | Base URL of the [S3](https://docs.aws.amazon.com/s3/)-compatible service (e.g. `https://<account>.r2.cloudflarestorage.com`). | — |
| `BACKUP_S3_BUCKET` | Target bucket name. | — |
| `BACKUP_S3_ACCESS_KEY` / `BACKUP_S3_SECRET_KEY` | S3 credentials. | — |
| `BACKUP_S3_REGION` | Bucket region (`auto` for Cloudflare R2, real region for AWS S3). | `auto` |
| `BACKUP_RETENTION_DAYS` | Days before objects are pruned (best-effort; prefer a bucket lifecycle rule). | `30` |
| `BACKUP_ENCRYPTION_KEY` | AES key for the backup payload — **must not** match `ENCRYPTION_KEY`. | — |

The IAM grant should be `PutObject` + `GetObject` only — retention is the bucket's lifecycle-rule job, never the worker's.

## TLS leaf-pin monitor

| Variable | Description |
|---|---|
| `TLS_LEAF_SPKI_PINS` | Comma-separated known-good leaf SPKI pins — `base64(sha256(DER subjectPublicKeyInfo))`, the same value the native client pins. Hold both the current and next pin during a dual-pin renewal window. See [certificate pinning](/security/certificate-pinning/). |

## Reverse-proxy trust & privacy

| Variable | Description | Default |
|---|---|---|
| `TRUST_PROXY_HOPS` | How many `X-Forwarded-For` hops to trust when reading client IPs (match your [reverse-proxy](https://en.wikipedia.org/wiki/Reverse_proxy) chain). | `1` |
| `TRUST_CF_CONNECTING_IP` | Set to `1` **only** when every public request terminates at Cloudflare; reads the visitor IP from `CF-Connecting-IP`. Mis-setting it lets a caller forge the rate-limit bucket key and the audit-log IP — leave it off behind nginx/Caddy/Traefik/ALB. | — |
| `IP_GEO_LOOKUP_URL` | HTTPS-only IP-geolocation provider URL. | `https://ipwho.is/{ip}` |
| `IP_GEO_LOOKUP_DISABLED` | Set to `1` to skip IP geolocation entirely. | — |
| `GEOLITE2_DIR` | Directory holding the offline GeoLite2 MMDB files. | `/opt/geolite2` |
| `AUDIT_LOG_RETENTION_DAYS` | Days before audit-log rows are purged (GDPR data-minimisation). | `365` |
| `HOST_METRIC_RETENTION_DAYS` | Days the per-minute host-load samples are kept. | `7` |

## Build-time / advanced

These are read at **build** time (`NEXT_PUBLIC_*`) or in narrow operational scenarios; they have no effect on the prebuilt GHCR image at runtime.

| Variable | Description |
|---|---|
| `NEXT_PUBLIC_DASHBOARD_SNAPSHOT` | Build-time toggle (default on) for the single-cell dashboard snapshot first-paint. Rebuild the image with `false` to fall back to the legacy multi-cell path. |
| `DEMO_MODE` | Puts the instance in read-only demo mode. |
| `DENSE_INTRADAY_RETENTION_ENABLED` | Set to `false` to disable the nightly dense intra-day retention drain. |

## .env.example

The repo ships the authoritative template — copy it and fill in the values:

```bash
cp .env.example .env
```

At minimum, set the required block:

```bash
DATABASE_URL="postgresql://healthlog:CHANGE-ME@db:5432/healthlog?schema=public"
POSTGRES_PASSWORD="CHANGE-ME"          # openssl rand -base64 24
NEXT_PUBLIC_APP_URL="https://health.example.com"
APP_URL="https://health.example.com"
ENCRYPTION_KEY="..."                   # openssl rand -hex 32 — NEVER change after first start!
API_TOKEN_HMAC_KEY="..."               # openssl rand -hex 32
```

Run `pnpm check-env` (or `pnpm check-env --file .env.production`) to verify every required variable is present before you deploy.
