HealthLog is configured through environment variables. Place them in a `.env` file next to your `docker-compose.yml`.

## Required

These variables **must** be set for HealthLog to start.

| Variable | Description | Example |
|---|---|---|
| `DATABASE_URL` | PostgreSQL connection string | `postgresql://healthlog:healthlog@db:5432/healthlog` |
| `SESSION_SECRET` | Used to sign sessions, 64 hex characters | `openssl rand -hex 32` |
| `ENCRYPTION_KEY` | AES-256-GCM key, 64 hex characters | `openssl rand -hex 32` |
| `API_TOKEN_HMAC_KEY` | HMAC key for API token hashing, 64 hex characters | `openssl rand -hex 32` |

:::danger
`ENCRYPTION_KEY` must **never** be changed after the initial startup. All encrypted database fields (tokens, OAuth credentials, API keys) are encrypted and decrypted with this key. Changing it will make all encrypted data permanently unrecoverable.
:::

## Important

| Variable | Description | Example |
|---|---|---|
| `NEXT_PUBLIC_APP_URL` | Public URL of the app. Used for Passkey RP-ID, OAuth redirects, and webhooks. | `https://health.example.com` |
| `APP_URL` | Alternative name for `NEXT_PUBLIC_APP_URL` (fallback) | `https://health.example.com` |
| `NODE_ENV` | `production` or `development` | `production` |

## Telegram

| Variable | Description |
|---|---|
| `TELEGRAM_WEBHOOK_SECRET` | Secret string used to verify incoming Telegram webhooks |

## Withings

| Variable | Description |
|---|---|
| `WITHINGS_REDIRECT_URI` | Optional override for the OAuth redirect URI |
| `WITHINGS_WEBHOOK_SECRET` | Secret used to verify incoming Withings webhooks |

## Logging (Loki)

| Variable | Description | Default |
|---|---|---|
| `LOG_LEVEL` | Minimum log level: `debug`, `info`, `warn`, `error` | `info` |
| `LOKI_ENDPOINT` | Loki push URL, e.g. `https://loki.example.com/loki/api/v1/push` | — |
| `LOKI_USERNAME` | Basic auth username for Loki | — |
| `LOKI_PASSWORD` | Basic auth password for Loki | — |
| `LOG_SAMPLE_RATE` | Log sampling rate (`0.0`–`1.0`) | `1.0` |
| `LOG_SLOW_THRESHOLD_MS` | Threshold for slow request warnings in ms | `3000` |
| `LOG_INCLUDE_STACK` | Include stack traces in error logs | `true` |

## Monitoring

| Variable | Description |
|---|---|
| `COMMIT_SHA` / `GIT_COMMIT` / `SOURCE_COMMIT` | Git commit hash of the build (used for health checks and error tracking) |
| `BUILD_TIMESTAMP` | Build timestamp |

## Web Push (Fallback)

These variables are optional — Web Push can also be configured through the admin settings. Environment variables serve as a fallback.

| Variable | Description |
|---|---|
| `VAPID_PUBLIC_KEY` / `NEXT_PUBLIC_VAPID_PUBLIC_KEY` | VAPID public key for Web Push |
| `VAPID_PRIVATE_KEY` | VAPID private key |
| `VAPID_SUBJECT` / `VAPID_EMAIL` | Contact URI or email for VAPID (`mailto:admin@example.com`) |

## Bug Reports

| Variable | Description |
|---|---|
| `GITHUB_ISSUE_TOKEN` | GitHub Personal Access Token with `repo` scope (legacy fallback — admin settings preferred) |
| `GITHUB_ISSUE_REPO` | Target repository in `owner/repo` format |

## Multi-Tenant / Scaling (v1.4+)

| Variable | Description | Default |
|---|---|---|
| `HEALTHLOG_PROCESS_TYPE` | `web`, `worker`, or `all` — splits HTTP traffic and pg-boss jobs into separate containers | `all` |
| `ENCRYPTION_KEYS` | JSON map of versioned keys, e.g. `{"v1":"<64-hex>","v2":"<64-hex>"}` (replaces single `ENCRYPTION_KEY` for installs that need rotation) | — |
| `ENCRYPTION_ACTIVE_KEY_ID` | Which key in `ENCRYPTION_KEYS` encrypts new writes | — |
| `API_TOKEN_HMAC_KEY` | HMAC-SHA-256 key for token hashing (already required) | — |
| `CODEX_OAUTH_CLIENT_ID` | When set, the **Connect with ChatGPT** button appears in Settings → AI and the device-code flow against `auth.openai.com` is enabled. Without it the API-key path is the only route | — |
| `CODEX_MODEL` | Operator-side default model slug for the ChatGPT-Codex provider. Falls back to `gpt-5.3-codex` (works on Plus and Pro). Override only if your plan tier needs a different default — the Codex backend will reject any slug that isn't in your plan's allow-list | `gpt-5.3-codex` |

See [Scaling & Operations](/self-hosting/scaling/) for the rotation workflow and the worker / web split.

## Off-Host S3 Backups (v1.4+)

Required **all-or-none**: setting any of these without setting the rest disables the backup silently. Use the variable names below exactly — they map 1:1 to the keys in [`.env.example`](https://github.com/MBombeck/HealthLog/blob/main/.env.example) and the worker reads them verbatim.

| Variable | Description | Default |
|---|---|---|
| `BACKUP_S3_ENDPOINT` | Base URL of the S3-compatible service (e.g. `https://<account>.r2.cloudflarestorage.com`) | — |
| `BACKUP_S3_BUCKET` | Target bucket name | — |
| `BACKUP_S3_ACCESS_KEY` | Access key | — |
| `BACKUP_S3_SECRET_KEY` | Secret key | — |
| `BACKUP_S3_REGION` | Bucket region (`auto` for Cloudflare R2, real region for AWS S3) | `auto` |
| `BACKUP_RETENTION_DAYS` | Days before objects are pruned (best-effort; prefer a bucket lifecycle rule) | `30` |
| `BACKUP_ENCRYPTION_KEY` | 64-hex / base64 32-byte key used to encrypt the backup payload — **separate** from `ENCRYPTION_KEY` | — |

The IAM grant must be `PutObject` + `GetObject` only — retention is the bucket's lifecycle-rule job, never the worker's.

## Auth & Privacy

| Variable | Description | Default |
|---|---|---|
| `TRUST_PROXY_HOPS` | How many `X-Forwarded-For` hops to trust when reading client IPs (matches your reverse-proxy chain) | `1` |
| `IP_GEO_LOOKUP_URL` | HTTPS-only IP-geolocation provider URL | `https://ipwho.is/{ip}` |
| `IP_GEO_LOOKUP_DISABLED` | Set to `1` to skip IP geolocation entirely | — |
| `AUDIT_LOG_RETENTION_DAYS` | Days before audit-log rows are purged (GDPR Art. 5(1)(e)) | `365` |

## .env.example

```bash
# === Required ===
DATABASE_URL=postgresql://healthlog:healthlog@db:5432/healthlog
SESSION_SECRET=          # openssl rand -hex 32
ENCRYPTION_KEY=          # openssl rand -hex 32 — NEVER change after first start!
API_TOKEN_HMAC_KEY=      # openssl rand -hex 32

# === App ===
NEXT_PUBLIC_APP_URL=https://health.example.com
NODE_ENV=production

# === Telegram ===
TELEGRAM_WEBHOOK_SECRET=

# === Withings ===
WITHINGS_REDIRECT_URI=
WITHINGS_WEBHOOK_SECRET=

# === Logging ===
LOG_LEVEL=info
LOKI_ENDPOINT=
LOKI_USERNAME=
LOKI_PASSWORD=

# === Monitoring ===
COMMIT_SHA=
BUILD_TIMESTAMP=

# === Web Push (optional, falls back to admin settings) ===
VAPID_PUBLIC_KEY=
VAPID_PRIVATE_KEY=
VAPID_SUBJECT=

# === Bug Reports ===
GITHUB_ISSUE_TOKEN=
GITHUB_ISSUE_REPO=
```
